## 1. POC 训练目标与判定

POC 阶段的目标不是达到 spec 的正式指标，而是证明两件事：

1. 自训模型确实从训练中学到了知识库里的知识；
2. 针对一部分提问能给出正确回答。

判定标准为 spec **SC-016**：与**未训练的同一基座**在同一套人工审核评测集（v1，60 题）上对比，
差异来自训练；"答对"按条和款都精确命中 gold 条款计。

### 1.1 证据

| SC-016 条件（v1，60 题） | 7B 基座 | 自训 7B（`exp-20261116-resume500`） | 判定 |
|---|---:|---:|---|
| ① 找对条 | 1/60 | **17/60** | Fisher 双侧 p≈4e-5，满足 |
| ② 条、款都精确命中 | 0/60 | **9/60 = 15%** | ≥10%，满足 |
| ③ 基座从未识别出的文件（30 题）找对文件 | 0/30 | **21/30** | Fisher 双侧 p≈4e-9，满足；这部分知识只能来自训练 |

辅助指标：引用格式（〔〕+ 版本日期）0/60 → 60/60；找对 gold 文件 16/60 → 45/60。

来源：E002 §6.2(1)；判定脚本 `scripts/experiments/e003/sc016.py`，输出 `artifacts/logs/e003/sc016.txt`。
基座 run 为 `run-20261117-022645`（E002 修复前误测基座的那次），自训 run 为 `run-20261117-081504`。

E003 补充了一条证据：在同一数据上追加训练一个 epoch 后，训练分布内题目的条级命中显著
提升（P2 28→51/100、P3 50→132/223，配对检验 p<1e-4）。知识确实是通过训练写进参数的，
不是偶然命中。

### 1.2 判定

SC-016 三项都满足，**POC 训练目标达成**。

### 1.3 边界（演示和汇报时要讲清楚）

- **能答对的比例不高**：款级 9/60、条级 17/60，离 spec 的 SC-002（召回 ≥90%）差距很大；
- **换个问法就容易答不对**：追加训练后，训练原题显著提升，人工评测集 v1 几乎不动
  （条级 17→18/60）。模型更像是记住了"这种问法对应这一条"，还没有学会举一反三；
- **答对的题不稳定**：两个 adapter 各自完全答对 9 题，重合的只有 6 题
  （`cand-001`、`002`、`008`、`012`、`029`、`045`）；
- **错误引用靠校验层兜底**：不存在的条款会被拦截删除，但"条款存在、只是不适用"拦不住。

## 4. 正式阶段的判断与待办

正式阶段的前提假设：基座可以换成更大的模型，训练数据更多，GPU 和显存满足该模型的训练需求。

### 4.1 判断

**只看训练后的模型，效果会比现在好，这一点比较有把握；但单靠模型更大、数据更多、
硬件更好，很难把条款精确定位做到 spec 要求的 90% 这一档。** 效果上限主要取决于
训练数据怎么构造，而不只是规模。

会明显变好的部分：

- **知识量和泛化**：更大的模型预训练见过更多法律文本，对没见过的问法更能联想到对应条款，
  这正是 E003 测到的瓶颈；
- **训练约束放开**：现在是 4-bit 量化 + LoRA rank 8（约 2,000 万可训练参数）；
  GPU 充足时可以用高精度、更高 rank 或全参数微调，也不再需要 fp16 溢出补丁；
- **训练轮数**：E003 已证明多训能显著提升训练分布内的定位。

不会因为规模自然解决的部分：

1. **核心问题是泛化，不是容量**：追加训练后原题大涨、v1 几乎不动。数据如果仍是每个条款
   只有一两种问法，换更大的模型也只能缓解，问题依旧存在；
2. **规模会增加难度**：现在 24 篇文档、约 3,800 个条款；到 1,000 篇时条款数可能多出
   几十倍，各地条例措辞相近甚至逐字重复，精确到"第几条第几款"更难；
3. **幻觉不会消失**：微调模型答错时往往给出看似合理的条款号，校验层拦不住
   "条款存在、只是不适用"的错误。

这一判断与公开研究的方向一致（场景不完全相同，只能说明方向，不能直接推算本项目的数字）：

- Ovadia 等（2023，*Fine-Tuning or Retrieval? Comparing Knowledge Injection in LLMs*）：
  单靠微调注入新知识，效果不如检索；
- Allen-Zhu、Li（*Physics of Language Models*，Part 3 系列）：模型能否在新问法下提取知识，
  关键在于训练数据中同一知识有没有多种表述；单纯重复相同样本帮助有限。
  E003"原题涨、v1 不涨"与此相符；
- Gekhman 等（2024，*Does Fine-Tuning LLMs on New Knowledge Encourage Hallucinations?*）：
  用微调灌输预训练没见过的新知识学得慢，还可能增加幻觉。

### 4.2 正式阶段要做的事

如果坚持纯训练路线，按预期收益从大到小：

1. **数据多样化**：每个条款配多种问法和场景（口语提问、案情描述、不提法名的提问），
   而不是同一问法重复多次。最便宜，也最对症；
2. **换更大的底座**：同一批数据上比较 7B、14B、32B。本项目目前**没有做过干净的规模对照**
   （1.5B 用的是旧数据集），"越大越好"在本项目中仍是推断；
3. **放开训练配置**：高精度、更高 rank 或全参数微调、多轮训练，用留出集监控过拟合。

立项前先做一次**小规模扩展验证**：

- 在租用 GPU 上，用多样化数据分别训练 7B 与 32B；
- 在扩充后的人工评测集（建议约 150 题，60 题统计功效不足）上比较，分开回答
  "多样化数据提升多少"和"模型变大提升多少"；
- 两者叠加后条级命中仍明显低于目标，再决定是否把检索作为正式方案的一部分。
  spec 已把"检索 + 模型"列为对照组与回退选项（research.md R12、
  contracts/system-interface.md 的 `RetrievalAssistant`），这条路是现成的。

其他保留到正式阶段的候选：

- E003 B2：恢复 knowledge 全量（可补齐当前 5 个零曝光 gold 条款）；
- 检索 + 自训模型：检索候选条款放进提示词，模型负责判断适用性与分析。
  这会改变 plan.md"推理时不检索"的设计，须按 SDD 流程先更新 spec/plan。
