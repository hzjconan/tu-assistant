## 训练技术

| 术语 | 解释 | 详见 |
|---|---|---|
| 全参数微调 | 更新模型的全部参数；效果上限高，内存需求极大 | [L2.1](./02-hardware.md#l21-训练时内存花在哪里) |
| 梯度 | 每个参数应该朝哪个方向调整、调整多少 | [L2.1](./02-hardware.md#l21-训练时内存花在哪里) |
| 优化器（Adam） | 根据梯度更新参数的算法，为每个参数额外保存历史状态 | [L2.1](./02-hardware.md#l21-训练时内存花在哪里) |
| 激活值 | 前向计算的中间结果，大小与样本长度成正比 | [L2.1](./02-hardware.md#l21-训练时内存花在哪里) |
| 量化 / 4bit | 用更少的位数存储参数；4bit 让 7B 权重从约 14GB 降到约 4.4GB | [L2.2](./02-hardware.md#l22-精度与量化4bit-是什么) |
| FP16 / BF16 | 每个参数用 16 位存储的两种格式，GPU 训练常用 | [L2.2](./02-hardware.md#l22-精度与量化4bit-是什么) |
| LoRA | 冻结原权重，只训练旁路的两个小矩阵 | [L2.3](./02-hardware.md#l23-lora只训练一小部分参数) |
| rank（秩） | LoRA 小矩阵的宽度，越大能学的越多、占用越多 | [L2.3](./02-hardware.md#l23-lora只训练一小部分参数) |
| 适配器（adapter） | LoRA 训练的产物，几十 MB，可与基座合并或单独加载 | [L2.3](./02-hardware.md#l23-lora只训练一小部分参数) |
| QLoRA | 4bit 量化的基座 + LoRA，消费级硬件的标准微调方式 | [L2.4](./02-hardware.md#l24-qlora--4bit-量化--lora) |
| 梯度检查点 | 少存中间结果、需要时重算，用约 14% 的速度换一半内存 | [L2.8](./02-hardware.md#l28-梯度检查点用时间换内存) |
| epoch（轮） | 把全部训练数据完整过一遍 | [L2.9](./02-hardware.md#l29-怎么估算训练时间) |
| loss | 模型预测的错误程度，训练中下降表示在学习 | [L2.6](./02-hardware.md#l26-本机实测数据怎么读)；[L5.3](./05-training.md#l53-看懂-loss-曲线) |
| 最大序列长度 | 单个样本允许的最大 token 数，超出部分被截断 | [L2.6](./02-hardware.md#l26-本机实测数据怎么读) |
| 超参数 | 训练前人为设定的参数（rank、学习率、轮数等），区别于模型自己学到的参数 | [L5.2](./05-training.md#l52-超参数逐项解释) |
| iteration（步） | 处理一个 batch 并更新一次参数；batch=1 时一步即一条样本 | [L5.1](./05-training.md#l51-一次训练的全过程) |
| batch size | 每步同时喂给模型的样本数 | [L5.2](./05-training.md#l52-超参数逐项解释) |
| 学习率 | 每步参数调整的幅度；最敏感的超参数 | [L5.2](./05-training.md#l52-超参数逐项解释) |
| LoRA scale / alpha | LoRA 旁路输出的放大系数；PEFT 用 alpha/rank，mlx_lm 只认 scale（alpha 不生效） | [L5.2](./05-training.md#l52-超参数逐项解释) |
| num_layers | 给模型最后多少层挂 LoRA（-1 表示全部层） | [L5.2](./05-training.md#l52-超参数逐项解释) |
| dropout | 训练时随机丢弃部分输出以防过拟合 | [L5.2](./05-training.md#l52-超参数逐项解释) |
| mask_prompt | loss 是否只计算 assistant 回答部分；mlx_lm 默认否 | [L5.2](./05-training.md#l52-超参数逐项解释) |
| train loss / val loss | 在训练样本 / 未训练过的验证样本上的 loss；后者衡量能否推广 | [L5.3](./05-training.md#l53-看懂-loss-曲线) |
| teacher forcing | 算 loss 时总给模型喂标准前文；与真实生成时"接着自己写"不同 | [L5.4](./05-training.md#l54-loss-降了--效果好本次就是反例) |
| 训练/推理分布不一致 | 运行时输入的形态（如是否带 system prompt）与训练数据不同，导致训练效果用不上 | [L5.4](./05-training.md#l54-loss-降了--效果好本次就是反例) |
| 冒烟评测 | 训练早期用少量真实评测题快速检查输出是否正常 | [L5.4](./05-training.md#l54-loss-降了--效果好本次就是反例) |
| 过拟合 / 欠拟合 | 死记训练集、对新样本变差 / 还没学够 | [L5.5](./05-training.md#l55-过拟合与欠拟合) |
| 容量 | 模型参数能装下的知识与能力，随规模增长 | [L5.6](./05-training.md#l56-模型规模与容量) |

## 评测

| 术语 | 解释 | 详见 |
|---|---|---|
| 校验前 / 校验后引用准确率 | SC-007 的两列指标：校验前（`ok / all`）衡量模型自身背诵准确度，校验后（`(ok+corrected) / all`）衡量加出处校验层后的交付底线 | [L6.4](./06-evaluation.md#l64-评测报告怎么读校验前后准确率incomplete-陷阱与人工评审闭环)；[L8.3](./08-lessons-and-next.md#l83-深度解读校验前引用准确率看清模型真本事与校验层的硬边界) |
| 人工评审表（ReviewComment） | 按 `eval/review-template.csv` 记录普法文章人工评审结论的 CSV（含 `verdict` 三态与可选 `dimension` 维度），用于事后汇总 SC-009 与 SC-010 | [L6.4](./06-evaluation.md#l64-评测报告怎么读校验前后准确率incomplete-陷阱与人工评审闭环) |
| 百分点（pp） | percentage point，衡量两个比率绝对差值的单位（`1 pp = 0.01`，如 `0.15 → 0.17` 为 `+2.0 pp`），用于区分相对涨幅与绝对变化 | [L6.5](./06-evaluation.md#l65-多版本对比与重复评测稳定性fr-035--sc-015为什么同口径和2-个百分点是对比的前提) |
| 重复评测波动（SC-015） | 同一系统版本在相同评测集与设置下重复评测时，各项有效百分比指标的最大跨度（`max - min`）；规格要求不超过 `2.0 pp` | [L6.5](./06-evaluation.md#l65-多版本对比与重复评测稳定性fr-035--sc-015为什么同口径和2-个百分点是对比的前提) |
| 固定对话脚本（Fixed Dialog Script） | 多轮评测用例中预先写定每轮用户输入（`input.script`）的评测方式，用于稳定复现追问、跳过追问与中途意图切换等场景（SC-001） | [L6.6](./06-evaluation.md#l66-评测集怎么设计才测出真能力多违法行为多轮意图脚本与防正则自证) |
| 多违法行为识别率（SC-004） | 衡量模型从一段含多个违法行为或多元主体的案情中逐项命中对应条款的比例；`gold.clauses` 须并入各违法行为的责任条款以避免 SC-003 误扣 | [L6.6](./06-evaluation.md#l66-评测集怎么设计才测出真能力多违法行为多轮意图脚本与防正则自证) |
| 贪婪解码（`temperature=0`） | 每一步总是选择预测概率最高的 token 的解码策略，理论上确定但工程中仍需通过重复评测（SC-015）验证端到端稳定性 | [L6.7](./06-evaluation.md#l67-重复评测确定性边界与ai-初审--人工终判闭环) |
| 前缀缓存（Prompt Cache） | 推理服务在内存中缓存历史请求 KV 状态的优化机制（如 `mlx_lm.server` 的 `LRUPromptCache`）；重复评测时需重启服务消除冷热态不对称 | [L6.7](./06-evaluation.md#l67-重复评测确定性边界与ai-初审--人工终判闭环) |
| 条款识别召回率 / 精确率（SC-002 / SC-003） | 召回率衡量标准答案条款里模型找出了多少，精确率衡量模型引出的条款里有多少是对的；本项目按题求宏平均 | [L6.8](./06-evaluation.md#l68-全指标计算方法宏微汇总与校验前后深化) |
| 宏平均 vs 微汇总（Macro vs Micro） | 宏平均先算每题分数再等权求均值（防止长题淹没短题，用于 SC-001~005），微汇总先把全部题的分子分母分别相加再相除（衡量每处引用/每篇文章的交付可靠性，用于 SC-006~011） | [L6.8](./06-evaluation.md#l68-全指标计算方法宏微汇总与校验前后深化) |
| 关联条款完整率（SC-005） | 衡量模型原稿（`final_raw`）引出某实体条款时，是否同步引出知识库中已确认的对应责任条款（`liability_for`）；独立于编排层的确定性兜底补充 | [L6.8](./06-evaluation.md#l68-全指标计算方法宏微汇总与校验前后深化) |
| SC-016 / Fisher 精确检验 | 本项目 POC 验收标准：通过双侧 Fisher 精确检验验证自训模型相对同基座在条级命中与基座未知文件子集上均显著提升（`p < 0.05` 且自训命中更高），且款/项级精确命中率 `≥ 10%` | [L6.8](./06-evaluation.md#l68-全指标计算方法宏微汇总与校验前后深化)；[L5.14](./05-training.md#l514-文件条款三级命中以及-sc-016-为什么按文件选题) |
| 错误归因与数据闭环迭代 | 把评测低分按类别拆解为“数据问题 / 模型能力问题 / 测量边界”，再反推下一轮训练数据的补齐方向、配比与质检关卡 | [L6.9](./06-evaluation.md#l69-用本项目评测结果分析薄弱类别并反推数据改进方向) |
