# 02 硬件与环境：一台 Mac 是怎么训练 7B 模型的

本章用本项目在 M1 Pro（32GB）上的实测数据，解释训练时内存和时间都花在哪里，以及我们用了哪些技巧让 7B 模型能在笔记本上训练。

---

## [L2.1] 训练时内存花在哪里

训练一个模型，内存里要同时放四样东西：

| 部分 | 是什么 | 大小取决于 |
|---|---|---|
| **权重** | 模型参数本身 | 参数量 × 每个参数的字节数 |
| **梯度** | 每个参数"该往哪个方向调、调多少" | 要训练的参数量 |
| **优化器状态** | 优化器（如 Adam）为每个参数额外记录的历史信息，通常是参数量的 2 倍 | 要训练的参数量 |
| **激活值** | 前向计算过程中的中间结果，反向计算梯度时要用 | **样本长度** × 模型宽度 × 层数 |

如果对 7B 模型做**全参数微调**，按常见的混合精度算法，每个参数大约要 16 字节（权重 + 梯度 + 优化器状态），
总共约 **112GB**，再加上激活值——远远超出 32GB。所以必须用 L2.2 ~ L2.4 的技巧。

## [L2.2] 精度与量化：4bit 是什么

每个参数用多少位来存，决定了权重占多少内存：

| 精度 | 每参数 | 7B 模型权重大小 |
|---|---|---|
| FP32 | 4 字节 | ~28GB |
| FP16 / BF16 | 2 字节 | ~14GB |
| **4bit** | 0.5 字节 | **~4.4GB**（实测下载文件大小） |

**量化**就是把高精度的数字近似成低精度存储，体积缩小到 1/4 ~ 1/7，代价是回答质量轻微下降。
对推理和 LoRA 训练来说，这个损失通常可以接受。

## [L2.3] LoRA：只训练一小部分参数

LoRA（Low-Rank Adaptation，低秩适配）的思路是：**原模型的权重全部冻结不动**，在每层旁边加两个很小的矩阵，只训练它们。

以模型里一个 4096 × 4096 的权重矩阵 W 为例：

- 全参数微调：要更新 W 的全部 1677 万个数。
- LoRA：额外加两个矩阵 B（4096 × r）和 A（r × 4096），用 B × A 表示对 W 的修改。
  取 r = 8 时，只有 4096 × 8 × 2 = **6.5 万**个参数需要训练，约为原来的 0.4%。

`r` 叫 **rank（秩）**，是 LoRA 最重要的超参数：越大，能学的东西越多，占用也越多。

本项目实测时，日志里有这样一行（0.5B 模型，16 层，rank 8）：

```
Trainable parameters: 0.594% (2.933M/494.033M)
```

意思是：模型共 4.94 亿参数，只训练其中 293 万个（0.594%）。

LoRA 的好处：

- **省内存**：梯度和优化器状态只针对这 0.6% 的参数，几乎可以忽略。
- **不容易训坏**：原权重不变，模型的通用能力不容易丢失。
- **产物小**：训练结果是一个几十 MB 的"适配器"文件，可以单独保存、切换、合并。

代价：能写进去的新知识有限。这也是为什么正式阶段要评估是否需要更大的 rank 或全参数微调。

## [L2.4] QLoRA = 4bit 量化 + LoRA

把 L2.2 和 L2.3 结合起来：基座权重用 4bit 存（省权重内存），只训练 LoRA 小矩阵（省梯度和优化器内存）。
这是在消费级硬件上微调大模型的标准做法。本项目本机训练用的就是 QLoRA。

## [L2.5] 为什么 Mac 能训练：统一内存与 MLX

- 一般的电脑，GPU 有自己独立的显存（如 RTX 5090 的 32GB），模型必须放进显存才能用 GPU 计算。
- Apple Silicon 的 Mac 采用**统一内存**：CPU 和 GPU 共用同一块内存，32GB 内存里的大部分都可以给 GPU 用。
- **MLX** 是 Apple 推出的机器学习框架，直接调用 Mac 芯片里的 GPU（通过 Metal）。本项目用的 `mlx-lm` 是基于 MLX 的大模型训练与推理工具。

> 注意：Mac 训练用的是芯片里的 **GPU**，不是 CPU。只用 CPU 训练会慢一个数量级以上。

## [L2.6] 本机实测数据怎么读

2026-11-10 在 M1 Pro / 32GB 上的实测（MLX，LoRA rank 8，16 层，batch 1）：

| 模型 | 场景 | 训练速度 | 峰值内存 |
|---|---|---|---|
| Qwen2.5-0.5B-4bit | 短样本 | ~1,150 tok/s | — |
| Qwen2.5-3B-4bit | 短样本 / ~5k token 长样本 | ~255 tok/s | 5.3GB / 13.6GB |
| Qwen2.5-7B-4bit | 短样本（≤750 token） | ~100 tok/s | ~9GB |
| Qwen2.5-7B-4bit | ~5k token 长样本 | ~97 tok/s | **23GB** |
| Qwen2.5-7B-4bit | 长样本 + 梯度检查点 | ~83 tok/s | **11.5GB** |
| Qwen2.5-7B-4bit | 推理（生成回答） | ~35 tok/s | 4.5GB |

几个读法：

- **tok/s**：每秒处理多少个 token，训练速度的标准单位。
- **模型越大越慢**：0.5B → 3B → 7B，速度大约按参数量反比下降（计算量和参数量成正比）。
- **长样本对速度影响不大，对内存影响很大**：7B 从短样本到长样本，速度只降了 3%，内存却从 9GB 涨到 23GB（原因见 L2.7）。
- 训练日志里 `train_loss` 从 2.8 降到 0.15（0.5B 那次）：loss 是"预测错误程度"，下降说明模型在学习。
  当时用的是假数据，loss 降得很低只说明"背住了"，不代表学得好——第 05 章会讲怎么正确看 loss。
- 日志里的警告 `Some sequences are longer than 512 tokens... will be truncated`：样本超过设定的最大长度时会被截断，
  被截掉的部分模型学不到。设定 `--max-seq-length` 时要参考训练数据的实际长度。

## [L2.7] 为什么长样本特别吃内存

L2.1 表里的**激活值**和样本长度成正比：样本越长，前向计算的中间结果越多，而这些结果要一直保留到反向计算时才能释放。

此外，模型最后一层要为样本中的**每个位置**计算一个"整个词表上的概率分布"。Qwen2.5 的词表约 15 万个 token，
5000 个位置 × 15 万 = 7.5 亿个数，仅这一项就要几 GB。

这也是 POC 没有选 Qwen3.5-9B 的原因之一：它的词表约 24.8 万，长样本时这部分内存更大。

普法文章这类长输出是本项目训练数据里最长的样本，所以它决定了峰值内存。

## [L2.8] 梯度检查点：用时间换内存

**梯度检查点**（gradient checkpointing）的做法是：前向计算时不保留全部中间结果，只保留少数"检查点"；
反向计算需要时，再从最近的检查点重新算一遍。

- 效果：7B 长样本峰值内存 23GB → **11.5GB**（减半）。
- 代价：多算了一遍，速度 97 → **83 tok/s**（慢约 14%）。

在 32GB 的机器上，23GB 已经很危险（系统和其他程序也要内存），所以训练长样本时**必须开**（`--grad-checkpoint`）。

## [L2.9] 怎么估算训练时间

```
训练一轮的时间 ≈ 训练数据总 token 数 ÷ 训练速度（tok/s）
```

本项目数据：25 篇文档约 0.66MB 纯文本，约 22 万字，约 17 万 token；
加上改写和对话样本后，训练数据约 1.5–2.5M token。

- 7B（开梯度检查点，~83 tok/s）：2.5M ÷ 83 ≈ 30,000 秒 ≈ **8.4 小时**，一晚能训完一轮。
- 1.5B：速度快数倍，调试流程时几小时内就能出结果。

**一轮**（epoch）是指把全部训练数据完整过一遍。通常要训 1–3 轮，轮数也是超参数（第 05 章）。

## [L2.10] 训练和推理的区别

| | 训练 | 推理 |
|---|---|---|
| 做什么 | 调整参数 | 用参数生成回答 |
| 需要存 | 权重 + 梯度 + 优化器状态 + 激活值 | 只要权重（加少量缓存） |
| 7B 实测内存 | 9–23GB | 4.5GB |
| 7B 实测速度 | ~83–100 tok/s（处理） | ~35 tok/s（生成） |

推理时一次只生成一个 token，且每个 token 都依赖前一个，无法并行，所以"生成速度"看起来比训练的"处理速度"低。
按 35 tok/s，一段 500 字的咨询回答约 10–20 秒，可以满足演示。

## [L2.11] 环境搭建与踩过的坑

- **Python 环境**：用 `uv` 为项目建独立的虚拟环境，不影响系统自带的 Python。
- **模型下载**：Hugging Face 直连和它新的 xet 传输协议在本机网络下只有约 1MB/s 甚至卡死。解决办法：
  ```bash
  export HF_ENDPOINT=https://hf-mirror.com HF_HUB_DISABLE_XET=1
  ```
  装了 `hf-xet` 后大文件会走 xet 协议，**不走** `HF_ENDPOINT` 镜像，所以必须同时禁用 xet。
- **许可证要逐个核实**：同一系列不同尺寸的许可证可能不同。Qwen2.5 的 0.5B/1.5B/7B/14B/32B 是 Apache 2.0（可商用），
  **3B 却是仅限非商业的研究许可**。我们测速时用过 3B，但它不能作为产品的基座。
- **测量内存的坑**：内存监视脚本记录的是"历史峰值"，每次测量前必须重启，否则会读到上一次的数字。

## [L2.12] Mac 和 RTX 5090 的对比

| | M1 Pro（本机） | RTX 5090 |
|---|---|---|
| 可用于训练的内存 | 32GB（和系统共用） | 32GB 显存（专用） |
| 7B 训练速度 | ~80–100 tok/s（实测） | 估计快 20–50 倍（未实测） |
| 训练精度 | 只能 4bit QLoRA | 可以 BF16 LoRA（更接近正式训练） |
| 软件生态 | MLX | CUDA + PyTorch，生态最完整 |

POC 只用 Mac；如果"每次改数据都要等一晚"成为瓶颈，再考虑接入 5090。
