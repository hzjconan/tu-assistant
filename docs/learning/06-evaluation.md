## [L6.1] SC-011：文章里有没有泄露用户提供的身份

SC-011 要求：普法文章中不得出现用户在对话中提供的真实姓名、单位等
身份信息（FR-030）。它的判定有一个容易想错的点：**按文章计数，不按题计数**。

### 分子与分母

- 分母：一次出稿中实际交付的文章篇数（以一级标题为篇界拆分——
  篇内的 `---`，如标题与正文之间的署名线，不另拆；含
  案例/以案说法/普法提示 段落标记才算一篇）；
- 分子：其中没有出现任何保护名称的篇数。

例：用户要求生成三篇文章，只有第二篇复述了用户提过的"栖梧样例厂"，
结果是 **2/3**，不是 0/1——逐篇计数才能区分"漏了一篇"和"全漏了"。

### 保护名称什么时候生效

用例在 `gold.protected_names` 里标注 `[{"name": "栖梧样例厂", "turn": 1}]`：
这个名称在第 1 轮用户消息中首次出现，**从该轮起**对之后交付的文章生效。
多轮脚本里，第一轮生成的文章不可能泄露用户第二轮才说的名字，
所以检查严格按标注轮次切分；初稿和修改稿分别检查、分别记录，
初稿的泄露在结果里可追溯，不会因为修改稿改干净了就被抹掉。

### 检查的边界

- 只看助手**实际交付的文章文本**（校验后的 `content`），
  用户提问里出现保护名称不算泄露，咨询轮复述也不算（那不是文章）；
- 没有 `protected_names` 标注的题是对照题，直接跳过，
  不作为 SC-011 的证据（"来源不明的空标注不能当作通过"）；
- 要求出稿的轮次如果没有可识别的篇章，例如把三个二级标题都写成加粗文字，仍在整轮交付文本中核对已生效的保护名称。命中时，`unparsed_leaks` 记录轮次和名称，报告单列待核查轮数。无法定位到具体篇次时，按篇分子和分母都不增加。拒答或空回复没有可评篇数；
- 同一轮同时包含约定格式和加粗标题格式时，只要拆出至少一篇，检查就只覆盖拆出的篇章。其他未识别篇章中的名称可能漏报，人工复核仍需阅读整轮交付内容；
- 检查的是**已标注**的名称：它依赖用例作者把"模拟用户身份"的虚构名
  写全，漏标的名称泄露了也发现不了。

实现：`metrics.article_identity_check`（`src/tu_assistant/eval/metrics.py`），
由 `run_eval` 在 `category == "article"` 时调用。

## [L6.2] 怎样读 SC-008 的拒答初筛结果

“如果单位无法提供工资条，您手里还有其他证据吗？”是在了解案情。仅凭“无法提供”给拒答分，会把这次追问算成模型拒绝作答。反过来，“这篇文章我写不了”已经拒绝交稿，词表只收“无法生成”就会漏掉它。为“超出”逐个添加否定前缀，也解决不了条件句、说话主体和委婉表达带来的判断差异。

咨询和文章使用同一套初筛。可识别的文章和带书名标记的条款引用优先阻断拒答判定，逐题结果的 `scores.refusal_evidence.blocked_by` 会写明原因。其余回复按句检查，在陈述句里找表示做不了或越界的短语，条件句和疑问句跳过。遇到编号追问或“请补充”时，只有范围短语能提供拒答证据；仅有能力短语时记 `follow_up`。

追问门槛让位于明确的越界说明，因为 article-007 的 rubric 允许拒答后引导改问。例如“库内没有证券期货依据，无法生成。如有劳动法需求，请补充说明。”会记录范围短语“库内没有”。“信息不足时我无法生成准确的文章，请补充……”仅有能力短语，仍按追问处理。`evidence` 保存实际命中的短语，`refused` 是初筛结果。

报告为两类题分别列出分数和分母。范围外正确拒答率计算应拒答题中判为拒答的比例，范围内误拒率计算应作答题中判为拒答的比例。所有常规范围内题都参加误拒统计，专设的 `false_refusal` 题额外列出分母，以便观察难题。没有对应题目时显示“无样本（0/0）”。在 T058 初期的 70 题基线中，v1 仅包含 1 道应拒答题（`article-007`）和 69 道常规范围内题（专设误拒题为 0 道）；经 T049 扩充至现行 98 题基线后，v1 共包含 **4 道应拒答题**（3 道 `refusal` + `article-007`）和 **94 道范围内题**（92 道常规范围内题 + 2 道专设 `false_refusal` 题）。

拒答初筛统一检测 `final_text`，多轮脚本只检查最后一轮。article-009、article-010 的首轮咨询不单独进入拒答分母。复核时结合用户问题、交付原文和 rubric 判断拒答理由是否适用。例如训练模板“暂不支持这项功能”能说明模型拒绝了请求，article-007 还要求说明缺乏适用的证券期货依据。

测试用六条严格预期失败（`xfail(strict=True)`）保留已知边界，断言记录人读后的期望值。

| 回复中的表达 | 初筛的已知错误 |
|---|---|
| 这个主题不会超出知识库范围 | 命中范围短语，误判拒答 |
| 这个主题未必超出知识库范围，请补充具体情况 | 范围证据优先，误判拒答 |
| 这篇稿子恕难执笔 | 缺少匹配的能力短语，漏判 |
| 没法据此写普法文章 | “据此”隔开“没法写”，漏判 |
| 若干问题超出知识库范围，无法生成 | 句首“若干”被当作条件前缀“若”，漏判 |
| 用人单位无法提供考勤记录的，应承担不利后果（劳动合同法第三十条） | 裸引用不触发结构门槛，“无法提供”误判拒答 |

以后若实现改变、其中一条开始通过，pytest 会报告意外通过并让测试失败，提醒维护者复核后更新记录。最终结论仍需人工复核。

## [L6.3] 文章脱敏接线后，怎样读 SC-011 与真实生成差异

T054/T055/T056 将确定性身份检查接入对话编排层后，评测时需要把**模型原稿**（`raw_content`）与**交付稿**（`content`）分开看，同时把**无稿**、**未拆篇**与**通过**区分清楚。

### 用 article-010 区分模型原稿、固定回放与真实续写

在 `article-010`（首轮自报姓名“陈实”与单位“启明电子厂”，第 2 轮写初稿，第 3 轮换建筑工地背景改稿）中，父模型 `exp-20261116-resume500` 在未接身份检查的基线 `run-20261120-024531` 里，第 2、3 轮原稿各复述了两次“陈实”，SC-011 为 **0/2**。

接入身份检查后，同一父模型出现两层对照：

1. **固定原稿回放**：直接重放基线保存的 T2、T3 原稿，身份检查层在两轮各命中 2 次人名，统一替换为同一虚构代称“甲某”，交付稿 SC-011 由 **0/2 → 2/2**；
2. **本机真实生成**（`run-20261122-090101`）：第 2 轮模型原稿仍复述 2 次“陈实”，编排层在写入 `Session.messages` 前将其替换为“甲某”；因此第 3 轮模型看到的助手历史已不含真实姓名，续写出的 T3 原稿本身也不再出现“陈实”（本轮 `person_replacements=0`），最终交付稿同样 **2/2** 通过。

这说明**交付前脱敏既兜底了本轮输出，也阻断了真实姓名通过助手历史向后续修改轮传播**；但在评估模型自身是否学会“虚构名称”时，仍需对照 `raw_content` 与每轮 `anonymize` 替换计数，不能只看交付稿的 `2/2`。

### 用 article-009 区分“无稿 / 未拆篇 / 通过”

`article-009` 虽有保护名称标注，但父模型在第 2 轮没有输出可被 `extract_articles` 拆出的标准篇章（实得篇数 `[0, 0]`）。SC-011 记为 `0/0`（报告注明“标注 2 题，其中 1 题有可评文章”），它表示**本题无可评文章，而非通过**；只有当 `unparsed_leaks` 为空且 `total > 0`、`passed == total` 时，才说明交付文章实际通过了检查。另外，若保护名称恰好与出处校验核准的条款标记或 KB 原文重合，系统会整轮暂缓交稿（零交稿），既不改动核准法条，也不计入 SC-011 分子分母，报告单独列出拦截的题号与轮次。

### 字面规则的覆盖边界

当前 `src/tu_assistant/chat/anonymize.py` 采用确定性本地规则，只覆盖**用户本会话中明确自报或职务语境下的常见单姓姓名**与**带专名的五类单位全称**（公司 / 厂 / 集团 / 医院 / 学校），并在交付稿中做字面全称替换。它**不覆盖**复姓与罕见姓氏、未加后缀的简称或车间/部门名（如“栖梧车间”）、谐音或变体写法，以及身份证号、手机号、工号、住址等其他个人信息；因此限定演示阶段仍须配合项目方逐稿预审。

## [L6.4] 评测报告怎么读：校验前/后准确率、`incomplete` 陷阱与人工评审闭环

一次完整评测产出 `results.jsonl`（逐题原始记录）和 `report.md`（汇总报告）。读懂报告的关键，是分清**模型自身能力**、**确定性校验层兜底**和**必须由人判定的语义质量**这三层信号。

### 1. 校验前 vs 校验后引用准确率（SC-007）

出处校验层（`src/tu_assistant/citation/verify.py`）对每处引用给出四种结论：`ok`（编号与原文都对）、`corrected`（编号对但模型背错了原文，校验层已替换为知识库原文）、`not_found`（库里查无此条，已删除）、`incomplete`（裸引用，或引用了多款条文却漏写款号且无法唯一定位）。

报告把 SC-007 拆成**校验前**与**校验后**两列，原因在于两列回答的是不同的问题：

- **校验前（`ok / 分母`）**：衡量模型自己背诵法条原文有多准，直接反映训练数据与微调效果；
- **校验后（`(ok + corrected) / 分母`）**：衡量加上确定性出处校验层后，最终交付给用户的法条原文有多可靠。

以 `run-20261120-183952`（70 题）为例，91 处引用中 `ok=63, corrected=8, not_found=0, incomplete=20`：
- 按严格全分母（含 `incomplete`）：校验前 `63/91 = 0.692`，校验后 `(63+8)/91 = 0.780`；
- 按已定位引用对照（排除 `incomplete`，共 71 处）：校验前 `63/71 = 0.887`，校验后 `71/71 = 1.000`。

能看到两层事实：一方面，只要编号定位明确，校验层把交付原文兜到了 100%；另一方面，真正拉低交付质量的瓶颈不是编造不存在的条号（`not_found=0`），而是 20 处未定位的 `incomplete`。

### 2. SC-006 与 `incomplete` 陷阱

只看 SC-006（出处标注完整率）很容易产生误判。在 `run-20261117-081504`（60 题）中，SC-006 是 `59/59 = 1.000`，看起来所有引用都标明了出处；但同一份报告的引用分布却有 **`incomplete=25`**（`ok=34, corrected=0, not_found=1, incomplete=25`）。

原因是两者的判定粒度不同：
- `citation_completeness`（SC-006）只检查引用是否带了书名和条号（`title` + `article_no`）；
- `verify_output` 在遇到**多款条文未写款号且引文无法唯一匹配某一款**时，会判定为 `incomplete`（因为无法确定该用哪一款原文核对）。

因此，报告的 SC-007 主口径坚持使用**严格全分母（包含 `incomplete`）**，同时在对照表中附列“已定位引用”口径和四态分布——避免这 25 处未经原文核对的引用同时从 SC-006 和 SC-007 中漏掉。

### 3. 为什么 SC-009 / SC-010 必须接入人工评审表

SC-001 ~ SC-008、SC-011 都有确定性或初筛脚本，但普法文章的两项核心质量无法靠简单正则替代人审：
- **SC-009（文章正确性）**：虚构案情是否真的满足所引条款的构成要件（例如把从业人员佩戴义务写成单位责任，格式与引用都合法，但法律逻辑错了）；
- **SC-010（文章多样性）**：同一次生成的多篇文章是否只是换人名地名的“换皮复读”，还是在主体类型、手段或情节上有实质差异。

因此系统提供标准模板 `eval/review-template.csv`（6 个必需列 `run_id,case_id,reviewer,verdict,comment,created_at` + 可选第 7 列 `dimension=correctness|diversity|other`，向下兼容纯 6 列；`dimension` 留空时，非拒答普法文章默认归入 `correctness`，应拒答题归入 `other`；`created_at` 建议统一填写 ISO 8601 格式以便修订去重）。评审完成后无需重跑模型，只需执行只读命令：

```bash
uv run tu eval report <run_id> --reviews <评审表.csv>
```

即可将人工评审结果与自动指标汇总到同一份报告中（SC-009 计 `pass / total`，SC-010 计实质重复率 `fail / total`，同时保留 `pass / minor_issue / fail` 三态明细；POC 阶段按 `题 × 评审人` 记录条数统计，而非逐篇展开）。

### 4. POC 目标值定位与历史产物只读保护

报告会在顶部显式注明：**POC 阶段列出的 SC-001 ~ SC-011 目标值仅供参考、用于观察差距，不作为验收条件**（POC 验收标准是证明模型从训练中学到了知识，即 SC-016）。此外，历史评测目录 `artifacts/eval/<run_id>/report.md` 受实验记录与 SHA-256 哈希锁保护（宪章原则 VI），`tu eval report` 默认输出到标准输出，且显式拒绝覆盖已有历史 run 的 `report.md`。

实现：`src/tu_assistant/eval/report.py`、`eval/review-template.csv`、`tu eval report`（T061 + T063）。

## [L6.5] 多版本对比与重复评测稳定性（FR-035 / SC-015）：为什么“同口径”和“2 个百分点”是对比的前提

看单次评测报告只能知道“现在有多好”；而做模型迭代时，更常见的问题是：**“换了训练数据、改了编排护栏、或者多训了一轮后，到底变好了还是变差了？”**以及**“如果指标涨了 1.5 个百分点，是真有提升，还是评测本身在抖动？”**

### 1. 为什么不能只看单一总分：聚合持平下的逐题翻转

以本项目两条真实 7B 历史评测 `run-20261117-081504`（`resume500`）与 `run-20261118-020130`（`epoch2`）在 `eval/cases/v1/reviewed.jsonl`（60 题 `clause_id`）上的对比为例：

- 只看主指标，两者的 **SC-002（条款召回率）完全相同，都是 `0.150`（9 通过 / 51 失败）**，很容易误以为“多训一轮什么也没变”；
- 但展开多指标与逐题变化后，真实情况截然不同：
  - **多指标分化**：**SC-003（精确率）下降 7.7 pp**（`0.265 → 0.188`，从 34 题有效引用扩大到 48 题但多引了不相关条款），而 **SC-007（引用准确率，校验前/后）上升 23.3 pp**（`0.567 → 0.800`，`incomplete` 从 25 降到 11）；
  - **逐题状态翻转**：虽然总通过数都是 9 题，但并非同一批 9 题——实际有 **3 题新通过（`fail→pass`：`cand-006`、`cand-021`、`cand-032`）**、**3 题退步（`pass→fail`：`cand-026`、`cand-039`、`cand-041`）**，始终通过的只有 6 题。

因此，`tu eval compare` 必须同时呈现**全量多指标差值（百分点 pp）**与**逐题状态变化（新通过 / 退步 / 多轮切换矩阵）**，避免总分掩盖结构性退化。

### 2. 对比前的可比性红线与目录扩题兼容

跨版本对比如果没有守住“同口径”，数字差值就没有意义。`tu eval compare` 在计算前强制执行以下校验：

- **同一知识库与同一评测集**：KB 版本名、评测集名、全部 `case_id` 及每题的 `category` / 用户提问 / `gold` 必须完全一致；
- **同一推理设置**：`temperature` 与 `use_system_prompt` 必须一致（缺失时判“无法确认”，退出码 `1`，不强行放行）；
- **拒绝诊断集**：命中 `diagnostics` / `probe` 路径或 `source=train_probe` 的 run 一律拒绝（退出码 `2`），防止把训练集探针当成正式评测对比；
- **目录型评测集扩题兼容**：如果历史 run 指向目录型评测集（如 `eval/cases/v1`），后来评测集往目录里追加了新题（如 T049 扩题），通用对比与 `--sc015` 在确认各 run 之间题号与内容完全一致、且全部结果题号均来自磁盘非诊断评测集后，允许按“历史共有子集”继续对比并在报告顶部明示扩题提示；而 `--sc016` 维持严格相等不变。

### 3. `tu eval compare` 三种模式的定位差异

| 模式 | 命令示例 | 回答的问题 | 退出码语义 |
|---|---|---|---|
| **常规对比（FR-035）** | `tu eval compare <r1> <r2> [<r3> ...] [--reviews csv] [--save]` | 跨版本/跨方案/改代码前后，各指标涨跌了多少（pp）、哪些题翻转了 | `0` 成功，`1` 可比性无法确认，`2` 输入冲突 |
| **稳定性门禁（`--sc015`）** | `tu eval compare --sc015 <r1> <r2> [--save]` | **同一系统版本**重复评测，全部有效百分比指标的最大波动是否 `≤ 2.0 pp` | `0` PASS，`1` FAIL 或无法判定，`2` 输入冲突（如跨模型） |
| **POC 验收（`--sc016`）** | `tu eval compare --sc016 <base> <trained>` | 自训模型相对同一未训练基座，是否显著学到了知识（条级/款级/未知文件三项） | `0` PASS，`1` FAIL 或无法判定，`2` 输入冲突 |

实现 `--sc015` 时有两个容易踩坑的边界：
1. **IEEE 754 浮点误差**：例如 `0.17 - 0.15` 在二进制浮点下是 `0.020000000000000018`，直接写 `spread <= 0.02` 会把恰好 2.0 pp 误判超限，因此判定采用 `spread <= 0.02 + 1e-9`；
2. **单侧无分母陷阱**：如果同一模型第一次评测产出 1 处有效引用、第二次产出 0 处（导致某项指标一侧为数值、一侧为 `None`），这本身就是显著不稳定，不能过滤 `None` 算成 `0.0 pp`，必须直接判 `FAIL`。

实现：`src/tu_assistant/eval/compare.py`、`tu eval compare`（T076 + T062）。

## [L6.6] 评测集怎么设计才测出真能力：多违法行为、多轮意图脚本与“防正则自证”

在 T049 中，我们把 `eval/cases/v1/` 从 70 题扩充到 98 题（新增 `multi_violation.jsonl` 10 题、`intent.jsonl` 10 题、`boundaries.jsonl` 8 题，覆盖全部 7 个类别）。看似只是“写 28 道题”，背后却有四个直接决定评测有没有效的工程与统计原则：

### 1. 为什么不能复述训练模板（防泄漏与 3-gram 去重）

如果评测题长得和训练合成模板几乎一样，模型靠死记模板就能拿高分，评测就失去了区分“真理解”与“背过题”的意义（宪章原则 V）。因此 T049 采用手工原创（`source="manual"`）并逐条核对知识库原文，再统一用字符级 3-gram Jaccard（`dedup_against_eval(..., overlap=0.8)`）对既有 v1 70 题、文章提示词模板池以及全部历史训练集（`ds-8410`、`ds-8247` 的 `train.jsonl` + `valid.jsonl`）做去重校验，确认高重合数为 **0**。

### 2. 测量工具与安全护栏的张力：“防正则自证”

翻看 `src/tu_assistant/chat/anonymize.py` 的 `classify_turn_intent` 与 `src/tu_assistant/eval/metrics.py` 的 `intent_score`，会发现一个很微妙的交互：

- **第 1 轮必须“零触发词”**：`classify_turn_intent` 会先用正则检查用户消息是否包含显式词（如“合法吗”“违法吗”“怎么办”“有什么法律责任”“写一篇普法文章”）。如果一道 `intent` 题的第 1 轮模糊开场不小心写了“这样合法吗”，**第 1 轮用户消息本身就会把 `session.intent` 直接置为 `"consult"`**——哪怕模型根本没理解意图，SC-001 也会被正则“伪确认”成 1.0！因此所有 `intent` 题的第 1 轮都必须经过 `classify_user_intent_signals(t1, article_task_active=False)` 校验 5 项信号全 `False`。
- **咨询收敛轮不靠正则走捷径**：对于 `gold.intent="consult"` 的第 2/3 轮，同样避免触发 `_RE_EXPLICIT_CONSULT`（改用“我想了解相关的法律规定，具体情况是……”等自然表达），迫使 `session.intent` 必须靠模型实际输出咨询结构（`违法行为认定/适用条款/法律责任`）或有效条款引用才转为 `"consult"`。
- **隐私护栏优先于测量便利（诚实记录边界）**：当用户在中途切换题（`intent-008..010`）里明说“帮我写一篇普法文章”时，T054 隐私脱敏护栏为了确保 FR-030“宁严勿漏”，会立即触发 `_RE_EXPLICIT_WRITE` 将 `intent` 切为 `"article"`。我们**不能为了评测指标去削弱隐私护栏**，因此诚实记录这一测量边界：这类题的自动 `SC-001` 只验证切换触发，真正是否按以案说法结构交付文章、是否正确引条与虚构主体，必须结合逐题 `rubric` 人工复核。

### 3. 为什么 `multi_violation` 的 `gold.clauses` 要并入 `violations[].liability`

在 `eval/runner.py` 中，同一道 `multi_violation` 题会同时算四个指标：`SC-004`（多违法行为识别率）、`SC-005`（关联责任补全率）、`SC-002`（召回率）和 `SC-003`（精确率）。如果 `gold.clauses` 只写实体行为条款、漏掉对应的法律责任条款，就会出现荒唐的“惩罚好模型”现象——模型按要求补全了法律责任条款（SC-005 升高），却被 SC-003 判成“多引了无关条款”而扣分！因此每道 `multi_violation` 题都通过单元测试强制要求：`set(gold.clauses) == union(v["clauses"] ∪ v["liability"])`。

### 4. 目录型平滑扩题：既补齐 7 类全指标，又不破坏历史基线

- 既有历史基线 `eval/cases/v1/reviewed.jsonl`（60 题，T076 `--sc016` 直接绑定）与 `eval/cases/v1/articles.jsonl`（10 题）保持**字节零改动**；
- `load_cases("eval/cases/v1")` 按 `sorted(p.glob("*.jsonl"))` 加载目录下全部 `.jsonl`，新增 3 个独立文件即平滑把 v1 从 70 题扩充至 98 题；
- 配合 T062 的子集对齐规则（`run.rows ⊆ chk.case_ids`），历史 70 题目录型评测仍可正常对比，而后续 T064 跑 7B 重复评测时一次就能产出覆盖 SC-001 ~ SC-011 全指标的完整报告。

实现：`eval/cases/v1/{multi_violation,intent,boundaries}.jsonl`、`src/tu_assistant/cli.py`（`tu eval cases review / promote` 增强）、`tests/unit/test_v1_multi_intent_eval.py`（T049）。

## [L6.7] 重复评测、确定性边界与“AI 初审 + 人工终判”闭环

> **本节解决什么问题**：为什么已经把 `temperature` 设成 `0`，还是要对同一个模型完整跑两遍评测来验证 SC-015（指标波动 `≤ 2.0 pp`）？当评测集里既有自动指标又有需要人读文章的 `SC-009 / SC-010` 时，怎样用外部大模型帮忙初审而不踩合规和统计坑？

### 1. `temperature=0` 不等于工程上天然零波动

评测阶段使用**贪婪解码（`temperature=0`）**：每一步只选概率最高的那一个 token，从数学公式看是完全确定的。但在真实本地推理链路里，仍存在两类常见的非确定性来源：

- **硬件与底层算子**：GPU（本机为 Apple Silicon Metal）并行浮点归约在极端平票或不同调度时序下可能出现微小舍入差，一旦某个 token 翻盘，后续整段文本就会分叉；
- **服务端前缀缓存（Prompt Cache）**：`mlx_lm.server` 进程内维护 `LRUPromptCache`，连续跑两轮时第 1 轮冷启动、第 2 轮命中缓存，KV Cache 的计算路径并不完全对称。

因此，T064 在两轮评测之间**优雅停服并重新冷启动 `tu serve model`**，且各自重跑 `ab.py 0` 路由冒烟，把隐藏状态彻底归零后再实测 SC-015。

### 2. 把“测量尺子稳不稳”与“模型考得高不高”分开看

T064 在冻结 7B 演示模型 `exp-20261116-resume500`、活跃 KB `kb-20261119-045641` 与完整 98 题（全 7 类 / 116 轮）上跑完两轮独立冷启动（`run-20261123-051432` 与 `run-20261123-053832`）：

- **测量工具极其稳定（SC-015 PASS）**：单轮墙钟耗时约 **21 分钟**（21 分 06 秒 / 20 分 56 秒），98/98 题 `final_raw` 与各轮交付稿 **100% 逐字一致**，12 项有效指标（含人工终审 `SC-009`）最大波动均为 **`0.0 pp`**（远低于 `≤ 2.0 pp` 阈值）；
- **POC 能力基线如实暴露**：例如 `SC-001` 意图确认率 `0.900 (9/10)`、`SC-006` 出处标注完整率 `0.919`、`SC-007` 已定位子集经校验层纠偏后从 `0.589` 升至 `0.973`、`SC-011` 身份无泄露 `1.000 (2/2)`；而 `SC-002` 条款召回 `0.121`、`SC-004` 多违法行为 `0.150`、`SC-009` 普法文章正确性 `0.000 (0/9)` 则清晰标出当前无检索纯 SFT（且未合入文章权重）的能力短板。

尺子稳了，后续换模型或上 RAG 时，哪怕只有 3–5 个百分点的提升，我们也能确信那是真实改进而不是随机噪声。

### 3. “AI 初审 + 人工终判”的三条工程边界

普法文章（`SC-009` 正确性、`SC-010` 实质重复率）无法靠纯正则判质量。T064 实践了“离线 DeepSeek 初审草稿 → 人工逐题复核终判”的流程，落地时必须守住三条边界：

1. **离线评测打分与线上运行物理隔离（宪章 III/IV）**：外部模型脚本放在 `scripts/experiments/t064/deepseek_review_articles.py`，复用到 `synth/llm.py`（`input_source="eval_case"`），**绝不侵入 `src/tu_assistant/{chat,runtime,ui,eval}/`**，只发虚构评测题、`rubric` 与本地模型交付稿，零接触 `inputs/` 与真实用户对话。
2. **AI 草稿与人类终判双文件隔离**：`report.py` 会把同一维度下不同 `reviewer` 的行全部计入分母；若把 `deepseek-chat-draft` 和 `user` 混在同一个 `--reviews` CSV 中，会导致双重计数。本任务把 AI 草稿留在 `artifacts/logs/t064/reviews-deepseek-draft.csv`，人工复核并纠偏（如修正 `article-009` 第 1 轮咨询轮误报泄露）后再单独写入 `eval/reviews/t064-reviews.csv`（仅含 `reviewer="user"`），且两轮 `run_id` 均覆盖（避免 `--sc015` 触发单侧 `None` 判 `FAIL`）。
3. **实得 `< 2` 篇不硬填 `diversity`**：`SC-010` 衡量的是“同一次生成的多篇文章是否实质重复”。本次 5 道多篇题在自动拆篇下实得均为 `0` 篇，若强行填 `fail` 会把“未出稿/拒答”误报成“100% 实质重复”，强行填 `pass` 又会误报成“0% 重复”；只在实得 `≥ 2` 篇时评判 `diversity`，未达 2 篇留空跳过，才能保证指标语义不失真。

实现：`scripts/experiments/t064/deepseek_review_articles.py`、`eval/reviews/t064-reviews.csv`、`docs/experiments/T064-eval-repeatability.md`（T064）。

## [L6.8] 全指标计算方法、宏/微汇总与校验前/后深化

### 2. 为什么有的指标用“宏平均”，有的用“微汇总”？

上表里最容易被忽略但对结论影响极大的设计，是**宏平均（Macro）**与**微汇总（Micro）**的分工：

- **条款识别能力（`SC-001`–`SC-005`）用宏平均（按题等权求均值）**：
  - `SC-002 / SC-003` 实际比较的是**去重后的标准条款 ID 集合**与**去重已解析的引用条款 ID 集合**（不是原始引用出现次数——例如 `mv-001` 出现 10 处引用，但去重后只对应 1 个条款 ID）。按真实口径统计 T064：`multi_violation` 10 题合计有 **45 条金标**（平均 **4.5 条/题**）、引出 **20 个去重 ID**（有引用的 9 题平均 **2.22 个/题**）；而 `clause_id` 60 题合计有 **60 条金标**（平均 **1.0 条/题**）、引出 **35 个去重 ID**（有引用的 35 题平均 **1.0 个/题**）；
  - 如果把所有题的集合直接合并做微汇总，1 道多违法行为长题在召回率上的权重约为 1 道单条题的 **4.5 倍**，在精确率上（按有效分母）约为 **2.2 倍**，少数长题会明显挤压绝大多数普通咨询题。按题等权求宏平均，才能反映“用户随机提一个问题，模型答对几成”的真实体验。
- **交付底线与格式可靠性（`SC-006`、`SC-007`、`SC-008`、`SC-011`）用微汇总（跨题合并分子分母）**：
  - 出处校验与身份脱敏守的是**每一处法条引用、每一篇交付文章**的底线。如果某道题一口气写了 8 处引用、错了一半，按题平均只占 1/98，会严重低估真实交付风险；按“处”或“篇”做微汇总，衡量的就是“用户看到任意一处引用或任意一篇文章时，它可靠/合规的概率”。

### 3. 深化校验前 vs 校验后（SC-007）：为什么 `corrected` 是把双刃剑

[L6.4](#l64-评测报告怎么读校验前后准确率incomplete-陷阱与人工评审闭环) 讲了校验前/后两列各自回答的问题。拿到 T064 全 98 题实测数据后，把不同类别拆开看，会发现一个更深层的现象：

- 全 98 题共 `163` 处引用，四态分布为 `ok=66, corrected=43, not_found=3, incomplete=51`：
  - 严格全分母（`163`）：校验前 `66/163 = 0.405` → 校验后 `(66+43)/163 = 0.669`（`+26.4 pp`）；
  - 已定位子集（排除 `51` 处 `incomplete`，共 `112` 处）：校验前 `66/112 = 0.589` → 校验后 `109/112 = 0.973`（`+38.4 pp`）。
- 表面看校验层把已定位引用兜到了 `97.3%`，但把 `43` 处 `corrected` 按类别拆开：
  - **`clause_id`（60 题）**：`ok=35, corrected=0, not_found=1, incomplete=24` —— 只要定位到条，模型几乎不背错原文；
  - **`multi_violation`（10 题）**：`ok=7, corrected=38, not_found=0, incomplete=12` —— **全集 43 处 `corrected` 中有 38 处（88.4%）集中在这 10 道长题里**！
- 抽查长题的真实输出就能看到原因：以 `mv-008` 为例，模型记住了大致的法律原则（公司改制时应听取工会意见），但在长文生成中**配错了条号**，写成了《公司法》第一百一十条第 2 款，并顺着自己的理解编了一段关于“民主管理”的引文；出处校验层查到《公司法》第一百一十条第 2 款确实存在（实际内容是股东查阅公司文件），于是忠实地把引文**替换成了“股东查账”的真实原文**（同类现象在 `mv-001` 更加极端：模型把阻挠建会与违法调岗反复错配到《上海市工会条例》第五十一条，导致 10 处引用全部 `corrected`，校验后贴出的却是“取缔非法组织”的条文）。结果：
  - 该题 `SC-007` 校验后飙升至 `1.000`；
  - 但正文分析仍在讲“民主管理”，而上方引用块贴的却是“股东查账”——**条款本身是真的，却与案情张冠李戴、引文与正文割裂**。

这正是校验层能力的硬边界：**确定性校验层只能保证“引文与所写条号逐字一致”，保证不了“所写条号适用于当前案情”**。因此读报告时，绝不能把 `SC-007` 校验后的高分当成“回答正确”，必须同时看：
1. **`SC-007` 校验前**（如果 `corrected` 突然暴增，往往意味着模型在靠蒙条号硬凑引用）；
2. **`SC-002 / SC-003`**（条号到底有没有命中标准答案）；
3. **正文与引文一致性人工核查**（尤其在长输出与普法文章中，T075 也复现了同类矛盾，见 [T075 实验记录](../experiments/T075-article-training.md)）。

### 4. 源码核对发现的 4 个工程度量边界

在核对 `src/tu_assistant/eval/{metrics.py,runner.py,report.py}` 时，有四处“按公式严格执行、但初看数字容易困惑”的工程边界，读报告时必须心里有数：

1. **为什么 `SC-006` 分母是 `160`，而 `SC-007` 全分母是 `163`？**
   - `metrics.py:citation_completeness` 解析的是**校验后**的 `verified.text`。在 T064 中，有 **3 处 `not_found`** 引用（`cand-048`、`refusal-001`、`refusal-002`）已被出处校验层替换为 `〔此处引用未通过校验，已删除〕`，不再匹配引用正则，因此 `SC-006` 分母恰好比 `SC-007` 少 `3`（`163 - 3 = 160`）。
2. **为什么 `SC-005` 是 `0.000 (n=2)`，是不是编排层关联补全失效了？**
   - 不是。`runner.py` 传给 `score_case_output` 的是末轮 `final_raw`（编排层在末尾追加 `**相关条款（系统补充）**` 之前的模型原稿）。实查 `run-20261123-051432/results.jsonl`：入分母的 `mv-008` 与 `intent-010` 在最终交付的 `final_text` 中**均已由编排层确定性补全了对应责任条款**（《公司法》第 186 条、《工会法》第 55 条）；`SC-005 = 0.000` 衡量的是**模型自己没有主动记住责任条款**，而非线上系统没补全。另外，只有当模型已解析的引用恰好命中 KB 26 条已确认 `liability_for` 起点时才进入分母，因此全 98 题仅 `n=2`。
3. **为什么 `SC-003` 有 6 道空 `gold.clauses` 的题也被计成了 `0.0`？**
   - `metrics.py:clause_recall_precision` 规定：只要 `cited_ids` 非空即计算 `precision = len(cited ∩ gold) / len(cited)`。对于 `article-008` 和 `intent-006..010` 这 **6 道以 `rubric` 评审、未填 `gold.clauses` 的题**，只要模型输出了任意合法条款引用，交集必为空、`precision` 即记为 `0.0`，把全集 `SC-003` 从 **56 题均值 `0.208`** 拉低到 **62 题均值 `0.188`**，并在失败清单中多出 `存在非标准引用（precision=0.000）`。为保持与已验收 T064 历史基线完全一致，POC 阶段不改代码，记为正式阶段评测口径优化项（空 `gold.clauses` 题应跳过 `precision` 计算）。
4. **多轮对话脚本只对最后一轮计分（`runner.py:50,108`）**
   - 自动计分中的 `SC-002 / SC-003 / SC-005 / SC-006 / SC-007 / SC-008` 均只评最后一轮（`runner.py` 只把末轮 `final_raw` / `final_text` 交给 `score_case_output` 与 `detect_refusal`；而 `SC-001` 检查前 3 轮、`SC-011` 与列表型 `expect_articles` 篇数检查为逐轮核对，`SC-009 / SC-010` 为人工评审，不受末轮限制）。因此 `SC-002 / SC-003 / SC-005 / SC-006 / SC-007` 里的 **163 处引用仅统计各题末轮**，而 `SC-008` 也只检查末轮。前面轮次发生的错误不会进入这些汇总指标——例如在 T064 中，`intent-001` 第 1 轮出现过 1 处 `not_found`（`〔此处引用未通过校验，已删除〕`），`intent-004` 和 `intent-007` 第 1 轮均整段误拒（“超出了我的知识范围”）、第 2 轮用户补充后即转入咨询，这些首轮问题都必须翻看逐轮日志才能发现。

### 2. 三层归因：区分“数据问题 / 模型能力问题 / 测量边界”

看到低分不要急着一概归咎于“模型太小”或“多训几个 epoch”。按这 5 组薄弱类别拆开看，每一类的主要症结并不相同：

1. **条款精确定位、细粒度款/项标号与邻近条辨析（`clause_id` 0.150、`exception` 0/3、`false_refusal` 0/2 选条错）**
   - **归因**：核心是**问法多样性不足、主/责条款选条偏差与条/款/项细粒度定位训练不够**（叠加纯参数记忆的容量上限）。[L5.12](./05-training.md#l512-如何区分曝光不足记忆不足与泛化不足e003) 的 E003 实验已经证明，模型对训练集原问法能答对，但换一种大白话问法就掉线；同时，全集 51 处 `incomplete` 中有 24 处来自 `clause_id` 多款条文漏写款号；而在 `exception` 3 题中，虽然正文分析方向均指出了法定例外，但实际选条和标号同时出问题——`exc-001` 的“适用条款”仍套用一般保密规定《劳动合同法》第二十三条、“法律责任”错引无关的第八十五条（解析出 `a23:p1`、`a85:p1`，精确率为 `0`），真正对应的第二十四条只在正文与责任段各出现一次且漏标 `第1款`（`incomplete=2`）；`exc-002` 引《劳动法》第四十二条未精确到 `第二项` 且裸引第四十一条；`exc-003` 把《法律援助法》第四十二条第三项错记为第二十四条；`false-refusal-001` 同样找对了《全民阅读促进条例》却错引邻近条号。
   - **反推数据改进**：① 提高每条条款的**多视角口语改写倍数与场景覆盖**（特别是地方性文件与易混条号）；② 对所有多款、多项条文，训练样本强制显式标注到 **`第X条第Y款（第Z项）`** 并在合成质检环节拒绝裸条号与合款混写；③ 针对“一般规定 vs 法定例外（区分主/责适用条与具体款/项）”和“同部法规邻近条号”补充**细粒度辨析样本**。

2. **多违法行为综合场景（`multi_violation` SC-004 0.150、`corrected` 占全集 88.4%）**
   - **归因**：**长结构化组合样本稀缺 + 跨法规条号记忆漂移**。单行为题里模型能写对 `ok=35, corrected=0`，一到多违法行为综合案情就频繁出现“知道违法但套错条号”（`mv-001/008`）和裸引用抬头（`mv-005` 4 处裸引用）。
   - **反推数据改进**：① 扩充**跨法规、多主体、2–3 个并行违法行为**的综合咨询样本，并在输出中强制“先逐项列出违法行为与主体 → 再为每项配齐实体条 + 责任条”的固定骨架；② 在合成质检关卡里增加**引文与正文一致性检查**（避免合成阶段就混入“条号存在但与分析脱节”的脏样本）。

3. **域外法律拒答边界（`refusal` 1/3，`refusal-001/002` 未拒答且编造法条）**
   - **归因**：**拒答种子总量过小、表达单一导致泛化不足**（而非缺少域外大类）。实查 `src/tu_assistant/synth/refusal.py:14-31`，16 条拒答种子中 `unsupported_feature` 占 6 条、`out_of_scope` 占 10 条，原本就包含“个人所得税怎么算？”、刑法盗窃罪、离婚抚养权、房东不退押金等域外法；但由于种子一共只有 16 条模板化短问句、拒答话术也各只有一种固定模板，模型即便见过“个人所得税怎么算？”，仍无法泛化到“专项附加扣除”（`refusal-001`）或“民间借贷利率”（`refusal-002`）这类具体业务问法，而是凭基座预训练记忆直接抢答并编造《个人所得税法》《民法典》引用块——哪怕校验层删掉了引用块，正文里的域外法律结论依然留在回复里，这是线上合规风险最高的一类错误。
   - **反推数据改进**：不是只挂几个大类名，而是大幅**提升拒答样本的问法与场景密度**（覆盖具体业务细节、多轮对话与隐含域外提问，如从“个税怎么算”扩展到专项附加扣除/汇算清缴等具体案情），同时**丰富拒答表述**（避免单一模板过拟合引发对正常请求的误拒），并严守“明确说明超出知识库范围、不得在正文中顺手给出域外法结论”。

4. **普法文章端到端生成（`article` SC-009 0/9、篇数 3/9、多篇误拒 3/9）**
   - **归因**：首先属于**模型基线边界**——冻结演示模型 `resume500` 从未见过文章训练样本；而在 T075 中把 46 条文章池（22 初稿 + 24 修改稿，其中 42 条进 `train` 按 6 倍过采样得 252 条、4 条进 `valid`）合入 `ds-8247` 续训后，虽使自动篇数从 `3/9` 升至 `7/9`，却出现条款定位退步（条级 17→14/60、款级 9→6/60）与正文/引文矛盾而放弃换模（详见 [L5.15](./05-training.md#l515-从已有-adapter-续训怎样看出新数据的作用) 与 [T075 实验记录](../experiments/T075-article-training.md)）。需严守实验证据边界：**训练层面的解释目前仍是待检验假设，现有对照无法单独确认哪一项造成退步**（包括：① 96.5% 旧样本复用叠加 Adam 重置与 `5e-5` 峰值学习率——但 E003 同样重复训练仍保条级 18/60，单靠重复训练不能解释全部退步；② 42 条文章样本 6 倍过采样且覆盖的 6 部法规缺少《劳动法》/《劳动合同法》高频主干题；③ 验证集每次仅抽 25 个 batch，单看 loss 漏检了正文错误与空标题循环）。
   - **反推数据改进**：若后续重启文章训练，须先补齐核心高频法规（《劳动法》《劳动合同法》《工会法》等）的单篇/多篇/修改/域外拒答完整家族，并通过控制变量实验（独立开发集 + 低学习率对照 + 人工核查正文/引文一致性）逐项验证上述假设。

5. **多轮意图确认（`intent` SC-001 表面 0.900，实为“零追问 + 3 题正则触发 + 3/10 首轮误拒”）**
   - **归因**：**追问行为完全没有学到，SC-001 0.900 是典型的“指标假象”**。逐题核对 `run-20261123-051432/results.jsonl` 全部 10 道 `intent` 题可见三个严峻事实：① **所有轮次的 `question_count` 全为 `0`**，模型一次反问/追问都没发起，**7/10**（`intent-001/002/005/006/008/009/010`）在模糊开场的第 1 轮就直接按 `consult` 作答，其中 `intent-008/009/010` 的标准意图本为 `article`、首轮判错；② 命中的 9 题里有 **3 题（`intent-008/009/010`）** 是在后续轮次用户发出 `explicit_write=True`（明确要求写普法文章）时由编排层正则直接切换的（正如 [L6.6](#l66-评测集怎么设计才测出真能力多违法行为多轮意图脚本与防正则自证) 所示，这只验证了切换触发，不能算模型自主确认）；③ **首轮范围内误拒多达 3/10**——除末轮也误拒的 `intent-003` 外，`intent-004` 与 `intent-007` 第 1 轮同样整段输出“超出了我的知识范围”，第 2 轮用户补充信息后即转入咨询（`intent-004` 第 2–3 轮均为 `consult`），因 SC-008 只测末轮而被掩盖。此外，末轮选条弱（`intent-004/006` 共 11 处 `incomplete` + 7 处裸引用），且 `intent-006..010` 受限于空 `gold.clauses` 触发 `precision=0.0`（测量边界）。
   - **反推数据改进**：这反推出两项紧迫动作：① 复查 `synth/dialogs.py` 生成的模糊开场 → 追问样本在训练集中的占比、清晰度与触发信号，**补强“信息不足时先追问、既不抢答也不首轮误拒”的多轮行为样本**；② 在多轮样本的收敛回答轮执行与单轮咨询同等严格的款级引用与零裸引用质检，并在评测侧补充首轮 `question_count` 与首轮误拒检查（不再只看末轮）。

### 3. 按投入产出比（ROI）排序的数据改进优先级清单

如果下一步继续沿微调路线迭代数据，按“降风险 + 提主指标”的投入产出比建议排序如下：

| 优先级 | 改进动作 | 针对的薄弱指标 | 预期收益与实施成本 |
|---|---|---|---|
| **P0（止血防高风险）** | 扩充域外拒答的**具体场景问法密度与多样化话术**（覆盖细化/隐含/多轮域外提问，突破 16 条短模板局限），同步补强**模糊开场主动追问**样本以压低首轮误拒与零追问 | `SC-008`（范围外 `2/4 → ≥95%`）、消除 `refusal-001/002` 抢答编造法条风险、修复 `intent` 零追问与 3/10 首轮误拒 | 样本量可控、直击最高合规风险与最严重行为短板 |
| **P1（提定位精度）** | 强制**多款/多项条文显式款项号**质检 + 扩充**多视角口语改写**与**一般/例外主责条及邻近条号辨析样本** | `SC-002`、`SC-003`、`SC-007`（压低 51 处 `incomplete`）、`exception`、`false_refusal` | 直接打击 60 题主干类别、24 处款号缺失及 `exc-001/002/003` 选条与细粒度定位失败 |
| **P2（补综合能力）** | 扩充**跨法规多违法行为组合样本**（实体条 + 责任条成对），合成质检加“引文-正文一致性”核查 | `SC-004`、`SC-005`、压低 `multi_violation` 38 处张冠李戴 `corrected` | 显著改善长回复的条号准确性与责任补全 |
| **P3（重做文章池）** | 按高频核心法规重构文章家族池（单篇/多篇/修改/域外拒答），以独立开发集与控制变量实验验证学习率与过采样假设 | `SC-009`、`SC-010`、文章篇数符合率与多篇误拒 | 样本构造与人审成本最高，应待 P0–P2 与架构路线确定后推进 |

> **与架构升级的边界**：数据构造与质检能显著修复拒答边界、格式规范、多款款号与常见场景，但**纯 7B 参数记忆在面对几十部法规、数千条细粒度条文时的检索上限**，靠堆 SFT 数据有明确天花板——更大底座（14B/32B）与 RAG 检索增强的取舍，详见 [L5.13](./05-training.md#l513-换更大的模型更多数据更好的硬件能解决什么)、[POC 训练阶段总结](../experiments/poc-training-summary.md)，以及后续第 8 章全项目复盘（T074）。
