## L6.1 SC-011：文章里有没有泄露用户提供的身份

SC-011 要求：普法文章中不得出现用户在对话中提供的真实姓名、单位等
身份信息（FR-030）。它的判定有一个容易想错的点：**按文章计数，不按题计数**。

### 分子与分母

- 分母：一次出稿中实际交付的文章篇数（以一级标题为篇界拆分——
  篇内的 `---`，如标题与正文之间的署名线，不另拆；含
  案例/以案说法/普法提示 段落标记才算一篇）；
- 分子：其中没有出现任何保护名称的篇数。

例：用户要求生成三篇文章，只有第二篇复述了用户提过的"栖梧样例厂"，
结果是 **2/3**，不是 0/1——逐篇计数才能区分"漏了一篇"和"全漏了"。

### 保护名称什么时候生效

用例在 `gold.protected_names` 里标注 `[{"name": "栖梧样例厂", "turn": 1}]`：
这个名称在第 1 轮用户消息中首次出现，**从该轮起**对之后交付的文章生效。
多轮脚本里，第一轮生成的文章不可能泄露用户第二轮才说的名字，
所以检查严格按标注轮次切分；初稿和修改稿分别检查、分别记录，
初稿的泄露在结果里可追溯，不会因为修改稿改干净了就被抹掉。

### 检查的边界

- 只看助手**实际交付的文章文本**（校验后的 `content`），
  用户提问里出现保护名称不算泄露，咨询轮复述也不算（那不是文章）；
- 没有 `protected_names` 标注的题是对照题，直接跳过，
  不作为 SC-011 的证据（"来源不明的空标注不能当作通过"）；
- 要求出稿的轮次如果没有可识别的篇章，例如把三个二级标题都写成加粗文字，仍在整轮交付文本中核对已生效的保护名称。命中时，`unparsed_leaks` 记录轮次和名称，报告单列待核查轮数。无法定位到具体篇次时，按篇分子和分母都不增加。拒答或空回复没有可评篇数；
- 同一轮同时包含约定格式和加粗标题格式时，只要拆出至少一篇，检查就只覆盖拆出的篇章。其他未识别篇章中的名称可能漏报，人工复核仍需阅读整轮交付内容；
- 检查的是**已标注**的名称：它依赖用例作者把"模拟用户身份"的虚构名
  写全，漏标的名称泄露了也发现不了。

实现：`metrics.article_identity_check`（`src/tu_assistant/eval/metrics.py`），
由 `run_eval` 在 `category == "article"` 时调用。

## [L6.2] 怎样读 SC-008 的拒答初筛结果

“如果单位无法提供工资条，您手里还有其他证据吗？”是在了解案情。仅凭“无法提供”给拒答分，会把这次追问算成模型拒绝作答。反过来，“这篇文章我写不了”已经拒绝交稿，词表只收“无法生成”就会漏掉它。为“超出”逐个添加否定前缀，也解决不了条件句、说话主体和委婉表达带来的判断差异。

咨询和文章使用同一套初筛。可识别的文章和带书名标记的条款引用优先阻断拒答判定，逐题结果的 `scores.refusal_evidence.blocked_by` 会写明原因。其余回复按句检查，在陈述句里找表示做不了或越界的短语，条件句和疑问句跳过。遇到编号追问或“请补充”时，只有范围短语能提供拒答证据；仅有能力短语时记 `follow_up`。

追问门槛让位于明确的越界说明，因为 article-007 的 rubric 允许拒答后引导改问。例如“库内没有证券期货依据，无法生成。如有劳动法需求，请补充说明。”会记录范围短语“库内没有”。“信息不足时我无法生成准确的文章，请补充……”仅有能力短语，仍按追问处理。`evidence` 保存实际命中的短语，`refused` 是初筛结果。

报告为两类题分别列出分数和分母。范围外正确拒答率计算应拒答题中判为拒答的比例，范围内误拒率计算应作答题中判为拒答的比例。所有常规范围内题都参加误拒统计，专设的 `false_refusal` 题额外列出分母，以便观察难题。没有对应题目时显示“无样本（0/0）”。当前 v1 包含 1 道应拒答题 article-007 和 69 道常规范围内题，专设误拒题为 0 道。

拒答初筛统一检测 `final_text`，多轮脚本只检查最后一轮。article-009、article-010 的首轮咨询不单独进入拒答分母。复核时结合用户问题、交付原文和 rubric 判断拒答理由是否适用。例如训练模板“暂不支持这项功能”能说明模型拒绝了请求，article-007 还要求说明缺乏适用的证券期货依据。

测试用六条严格预期失败（`xfail(strict=True)`）保留已知边界，断言记录人读后的期望值。

| 回复中的表达 | 初筛的已知错误 |
|---|---|
| 这个主题不会超出知识库范围 | 命中范围短语，误判拒答 |
| 这个主题未必超出知识库范围，请补充具体情况 | 范围证据优先，误判拒答 |
| 这篇稿子恕难执笔 | 缺少匹配的能力短语，漏判 |
| 没法据此写普法文章 | “据此”隔开“没法写”，漏判 |
| 若干问题超出知识库范围，无法生成 | 句首“若干”被当作条件前缀“若”，漏判 |
| 用人单位无法提供考勤记录的，应承担不利后果（劳动合同法第三十条） | 裸引用不触发结构门槛，“无法提供”误判拒答 |

以后若实现改变、其中一条开始通过，pytest 会报告意外通过并让测试失败，提醒维护者复核后更新记录。最终结论仍需人工复核。

## [L6.3] 文章脱敏接线后，怎样读 SC-011 与真实生成差异

T054/T055/T056 将确定性身份检查接入对话编排层后，评测时需要把**模型原稿**（`raw_content`）与**交付稿**（`content`）分开看，同时把**无稿**、**未拆篇**与**通过**区分清楚。

### 用 article-010 区分模型原稿、固定回放与真实续写

在 `article-010`（首轮自报姓名“陈实”与单位“启明电子厂”，第 2 轮写初稿，第 3 轮换建筑工地背景改稿）中，父模型 `exp-20261116-resume500` 在未接身份检查的基线 `run-20261120-024531` 里，第 2、3 轮原稿各复述了两次“陈实”，SC-011 为 **0/2**。

接入身份检查后，同一父模型出现两层对照：

1. **固定原稿回放**：直接重放基线保存的 T2、T3 原稿，身份检查层在两轮各命中 2 次人名，统一替换为同一虚构代称“甲某”，交付稿 SC-011 由 **0/2 → 2/2**；
2. **本机真实生成**（`run-20261122-090101`）：第 2 轮模型原稿仍复述 2 次“陈实”，编排层在写入 `Session.messages` 前将其替换为“甲某”；因此第 3 轮模型看到的助手历史已不含真实姓名，续写出的 T3 原稿本身也不再出现“陈实”（本轮 `person_replacements=0`），最终交付稿同样 **2/2** 通过。

这说明**交付前脱敏既兜底了本轮输出，也阻断了真实姓名通过助手历史向后续修改轮传播**；但在评估模型自身是否学会“虚构名称”时，仍需对照 `raw_content` 与每轮 `anonymize` 替换计数，不能只看交付稿的 `2/2`。

### 用 article-009 区分“无稿 / 未拆篇 / 通过”

`article-009` 虽有保护名称标注，但父模型在第 2 轮没有输出可被 `extract_articles` 拆出的标准篇章（实得篇数 `[0, 0]`）。SC-011 记为 `0/0`（报告注明“标注 2 题，其中 1 题有可评文章”），它表示**本题无可评文章，而非通过**；只有当 `unparsed_leaks` 为空且 `total > 0`、`passed == total` 时，才说明交付文章实际通过了检查。另外，若保护名称恰好与出处校验核准的条款标记或 KB 原文重合，系统会整轮暂缓交稿（零交稿），既不改动核准法条，也不计入 SC-011 分子分母，报告单独列出拦截的题号与轮次。

### 字面规则的覆盖边界

当前 `src/tu_assistant/chat/anonymize.py` 采用确定性本地规则，只覆盖**用户本会话中明确自报或职务语境下的常见单姓姓名**与**带专名的五类单位全称**（公司 / 厂 / 集团 / 医院 / 学校），并在交付稿中做字面全称替换。它**不覆盖**复姓与罕见姓氏、未加后缀的简称或车间/部门名（如“栖梧车间”）、谐音或变体写法，以及身份证号、手机号、工号、住址等其他个人信息；因此限定演示阶段仍须配合项目方逐稿预审。
