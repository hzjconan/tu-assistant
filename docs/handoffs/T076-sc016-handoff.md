## 2. 加载两个 run，核对可比性

在 `src/tu_assistant/eval/compare.py` 实现结果加载。每个 run 读取 `artifacts/eval/<run_id>/manifest.json` 和 `results.jsonl`。读取清单可复用 `read_manifest`。[清单工具](../../src/tu_assistant/manifest.py) · [结果写入逻辑](../../src/tu_assistant/eval/runner.py)

1. 使用清单 `inputs.kb` 指向的历史 SQLite 知识库取得文件名与文档 ID 的对应关系。核对两边知识库版本、温度和是否使用 system prompt。两次运行的模型路由不同，整份 `config_hash` 可以不同。
2. 按 `case_id` 对齐，检查重复 ID、两侧用例集合、用例类别、用户提问和 gold 条款。SC-016 只统计 `category == "clause_id"` 的条款识别题。当前 60 题每题恰有一个 gold 条款，遇到缺失或多个 gold 的条款题时，报出用例 ID 和原因。用例行顺序不影响结果。
3. 兼容两种历史清单。基座 run 的 `inputs.exp_id` 也写着训练实验名，但 `config.model` 是实际请求的 7B 基座名。自训 run 的 `config.model` 为 `default_model`，实际基座和 adapter 实验记录在 `config.base_model`、`config.exp`。按角色核对这些字段，输出时标清两边 run ID。

## 3. 实现三项计分

将计分逻辑放在 `eval/compare.py`，接受已对齐的结果及历史知识库文件名映射，返回各项计数、分母、适用的 p 值和判定。实验模块在导入时会读取固定路径并执行分析，正式模块应直接提取所需算法。双侧 Fisher 使用标准库 `math.comb`，与 E002 的列联表和双侧口径对齐。[E002 宽松解析与 Fisher 实现](../../scripts/experiments/e002/review_stats.py) · [E003 判定脚本](../../scripts/experiments/e003/sc016.py)

1. **条级命中**。从每题的 `final_raw` 宽松解析引用，沿用 E002 的文件名规范化和匹配顺序。单独出现匹配的《文件名》可计文件命中。若还给出条号，则按“文件 ID + 条号”计条级命中，后面带款、项也算。每题最多计一次。以两边的“命中、未命中”构成列联表。自训命中更多且双侧 p < 0.05 时通过。
2. **款／项级命中**。逐题判断完整 gold 条款 ID 是否在自训结果的 `scores.cited_clause_ids` 中。该字段来自出处校验后的精确定位，字段存在但列表为空表示未命中。命中比例 ≥ 10% 时通过。[严格计分字段的来源](../../src/tu_assistant/eval/metrics.py)
3. **基座从未识别出的文件**。先收集基座曾在对应题目上找对的全部 gold 文件。再选出 gold 文件不在该集合中的题，作为两边共用的子集。同一文件只要被基座找对过一次，该文件对应的所有题都排除。仅在该子集统计文件命中，自训命中更多且双侧 Fisher p < 0.05 时通过。子集为空时显示“无法判定”，总结果不能通过。

## 4. 接入命令行

在 `src/tu_assistant/cli.py` 的 `eval_app` 注册 `compare`。指定 `--sc016` 时接收两个 run ID，沿用评测命令的 `--artifacts` 目录选项。输出列出每项命中数和分母、条件①③的 p 值、各项判定及总判定。PASS 返回 0，FAIL、无法判定或输入错误返回非零，提示中区分原因。[现有 CLI](../../src/tu_assistant/cli.py)

## 5. 用小样本验证分支

在 `tests/unit/test_compare.py` 使用临时目录、自编文件名、小型 SQLite 库和两份假 run。覆盖以下情况后运行测试。

- **计分**。仅有文件名、条对款错、条款精确命中各做一例。检查严格命中恰好 10% 的边界，使用已知列联表核对双侧 Fisher p 值。
- **文件子集**。同一文件安排两题，基座一题命中、一题未命中，两题都应退出条件③的分母。再测所有文件都被识别时的“无法判定”。
- **可比性**。打乱结果顺序仍得到相同结果。构造重复 ID、两侧 ID 不一致、同 ID 不同 gold、评测设置不同及多 gold 用例，检查错误提示。
- **CLI**。用 Typer 测试入口走一次完整读盘流程，覆盖旧基座清单、成功、指标未达标和输入错误，检查输出及退出码。

```sh
uv run pytest tests/unit/test_compare.py
uv run pytest
uv run ruff check src tests
```
