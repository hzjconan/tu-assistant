## 1. 评审发现的问题

### P1 · 用正则判断回复是否拒答，方法不可靠

`RE_ARTICLE_REFUSAL_SCOPE` 经过六轮复审，每轮补上复审给出的反例，现在已有 16 个排除条件。中文的否定、疑问、条件、委婉说法没有穷尽，这样补下去停不下来。它只保证列举过的句子能通过。用当前代码实测：

| 回复（无文章交付） | 现结果 | 应为 |
|---|---|---|
| 如果超出本知识库的收录范围，我会直接告诉您。请问您想了解哪方面？ | True | False，条件句 |
| 这个主题超出知识库范围了吗？您能再说具体些吗？ | True | False，疑问句 |
| 如果单位无法提供工资条，您手里还有其他证据吗？ | True | False，追问 |
| 这个主题未必超出知识库范围，请补充具体情况。 | True | False，追问 |
| 抱歉，证券期货内幕交易不属于我能处理的领域，这篇文章我写不了。 | False | True |
| 抱歉，本期我暂不支持这项功能……（`synth/refusal.py` 的 `unsupported_feature` 模板） | False | True |

误判和漏判两类都有，复审只沿着把追问当拒答这一个方向找过反例。[现有拒答判定](../../src/tu_assistant/eval/metrics.py)

### P2 · SC-008 同时用两套口径

咨询题用 `REFUSAL_MARKERS`，其中“不在”“超出”这类单词一碰到就算拒答。例如范围内回答里出现“用人单位不在规定时间内支付工资”，会被判成误拒。文章题用的是更严的正则。两者在 `report.md` 里合并成同一个“拒答正确率”。v1 现有 60 道咨询题都是 `clause_id` 类，没有 `refusal`/`false_refusal` 题，所以统一口径不影响基线和 T076 的历史对比。[报告汇总](../../src/tu_assistant/eval/runner.py)

### P2 · 拆篇失败时 SC-011 不报泄露

`extract_articles` 只认 `## 案例` 这类精确的二级标题。模型如果写成 `**案例**`，一篇也拆不出来，身份检查就显示“无可评文章”，文中出现的保护名称也报不出来。篇数检查会判失败，但不会提示泄露。[拆篇与身份检查](../../src/tu_assistant/eval/metrics.py)

## 2. 设计约束

- 判定分两层。第一层是结构门槛：输出格式有约定（[citation-format §4、§5](../../specs/001-legal-clause-assistant/contracts/citation-format.md)），按约定判断，结果稳定。第二层是短语证据：短语表固定、按子串匹配、不用正则，表在代码里一眼能看全。
- 不再用 lookbehind，也不再写跨词通配的正则。实施或复审中再遇到误判，先判断它是否属于已有的结构门槛或句子规则能覆盖的类别。不属于的，写进“已知局限”测试和学习文档，由人工复核兜底，不再追加规则。
- 自动判定只作初筛，最终结论以人工评审为准（T061/T063）。每题都要记录判定依据。
- 不改 `eval/cases/v1/`、`chat/prompts.py`、`synth/`。在 system prompt 里规定固定的拒答话术会改变模型行为，影响 T076 的对比口径。这个方案留给 T057/T075 评估，本任务只在第 7 节记录。

## 3. 统一拒答判定

在 `eval/metrics.py` 新增 `detect_refusal(text: str) -> dict`，返回 `{"refused": bool, "evidence": str | None, "blocked_by": str | None}`，按顺序判定：

1. **结构门槛**，命中任一条就是 `refused=False`，`blocked_by` 记原因：
   - `"article"`：`extract_articles(text)` 不为空；
   - `"citation"`：`parse_citations(text)` 中有带书名标记的引用（`c.title` 非空）。只写“第N条”的裸引用不算，因为拒答时建议“可改问劳动法相关问题”也算合理；
   - `"follow_up"`：文本包含追问编号列表（复用 `chat/orchestrator.py` 的 `RE_QUESTION_LINE`，直接导入，不要复制），或包含“请补充”。
2. **按句切分**：用 `。！？!?` 和换行切句。以 `？`/`?` 结尾的疑问句，以及去掉首尾空白后以“如果、假如、若、要是、一旦”开头的条件句，都不能作为证据。
3. **短语证据**：在其余句子中按子串查找两张表，命中第一条时记入 `evidence`（只记该短语本身），`refused=True`。
   - 能力表（表示做不了）：无法生成、无法撰写、无法回答、无法提供、无法为您、不能生成、不能写、写不了、没法写、帮不上忙、暂不支持、不便推测作答，可酌情补充同类说法。
   - 范围表（表示越界）：超出了我的知识范围、超出本知识库、超出了本知识库、超出知识库、不在本知识库、不在知识范围、本知识库未收录、库内没有、库内无、本知识库缺乏、缺乏相关依据、缺乏适用于、收录范围之外、知识范围之外。
   - 否定检查只用一条规则：范围表短语以“超出”开头时，如果它前一个字是“未、没、有、否、不”之一，这次命中作废（覆盖“未超出”“没有超出”“是否超出”“是否有超出”）。用一个几行的辅助函数实现，不用正则。
4. 都没有命中：`refused=False`，`blocked_by=None`。

之后：

- `refusal_correct(text, should_refuse)` 改为调用 `detect_refusal`，函数签名不变。删除 `REFUSAL_MARKERS`。
- `article_refusal_correct` 改为调用 `detect_refusal`，或者删掉它，让运行器直接调用 `refusal_correct(..., True)`，两种都可以，但运行器里只能保留一条判定路径。删除 `ARTICLE_REFUSAL_EXPLICIT`、`RE_ARTICLE_REFUSAL_SCOPE` 及其注释。
- 在 `runner.py` 的两个拒答分支（`refusal/false_refusal` 和文章 `should_refuse`），把 `detect_refusal` 的结果原样写入 `r["scores"]["refusal_evidence"]`。
- 在 `report.md` 的 SC-008 一行，口径列改为“SC-008（自动初筛，依据见 results.jsonl 的 refusal_evidence）”。

## 4. 拆篇失败兜底

1. 给 `article_identity_check` 增加参数 `article_turns: set[int] | None = None`，表示要求出稿的轮次（从 1 起数）。在运行器里由 `expect_articles` 推出：列表中非 `null` 且大于 0 的位置；如果是 int，则只取最后一轮。
2. 对 `article_turns` 中的每一轮，如果 `extract_articles` 结果为空，但整轮 `content` 包含已生效的保护名称，就在返回值的 `unparsed_leaks` 中记录 `{"turn": i, "leaked": [...]}`。这些记录不计入 `passed/total`，分母口径与 T058 一致。没有拆出文章时，原因写成“未识别出文章结构”，与拒答、空回复造成的“无可评文章”分开。
3. 咨询轮（`null`）不做这项检查，咨询回复复述名称是正常的。
4. `report.md` 的 SC-011 一行：有 `unparsed_leaks` 时，在括号里追加“另有 N 轮未识别出文章结构但含保护名称”。
