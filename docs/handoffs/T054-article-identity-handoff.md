## 实施步骤

### 1. 从本会话的用户消息提取候选

在 `chat/anonymize.py` 实现确定性规则。每轮先看已到达的用户输入，按出现次序取人名和单位名。保留 `Session.user_entities: set[str]` 的兼容语义，另在会话内维护有序的原名、类别与代称映射。模型创作的角色、系统提示、评测 gold 均不能成为抽取来源。

- **人名。** 覆盖“我叫〈姓名〉”“我是〈单位〉的工会主席〈姓名〉”等自报身份和职务语境，限常见姓氏加一至二字名，并检查两端词界。验收同时给出“工会主席任期内 / 安排 / 应当 / 管理 / 向职工反映 / 要钱”六组普通用法，均应零候选。复姓如纳入须列出支持清单和正反例。
- **单位。** 识别有专名成分、以公司 / 厂 / 集团 / 医院 / 学校结尾的全称，保留“在〈单位〉做质检”“我是〈单位〉的……”中的精确边界。过滤“某餐饮公司、某厂、建筑公司、有限责任公司、股份有限公司、外国公司、分公司”等虚构称谓或行业、法定泛称；“某”“厂”“公司”等作词素时不能截取出假单位，如“厂房 / 厂区 / 厂长 / 公司法”。“青砾建筑公司”一类有专名的全称仍须识别。新增不同于 v1 专名的五种后缀夹具。
- **输入中的法律材料。** 抽取前划去书名、正式引用标记及其可界定的法条原文，保留同条消息中的案情和紧接引文的叙述。加一组法名含单位后缀、同句前后又自报姓名和单位的用例。只替换已提取全称的字面命中。派生简称、变体写法、罕见姓氏，以及身份证号、电话、工号、地址均超出本次覆盖。

### 2. 为出稿和改稿确定本轮意图

本轮明确写稿或改稿的请求优先，包含“普法短文”“把宣传栏素材整理成一篇普法案例”“写一篇工会宣传栏短文”。已请求出稿时，即使整段无标准 Markdown 标题，仍检查这次回复。记住本轮文章任务，以便非标准初稿后的“再通俗一点”“换个主体再发一版”沿用检查。没有明确请求时，结合实际文章小节及上下文判断；单个“案例”不足以认定出稿。明确否定写稿、转为咨询时清除续改状态。检查范围覆盖标题、署名、所有篇和篇间文字。

统一维护会话意图与检查所用的判定，明确写稿 / 续改、切回咨询分别在 `Reply.intent` 中体现为 `article`、`consult`；模糊开场按当前对话状态处理。测试“不要写文章，只问这个案例怎么处理”“这篇文章引用的条款适用吗”“单位不让发普法文章合法吗？”三种咨询与“整理成一篇普法案例”的区别，并用同一组回复断言 `intent_score` 的前三轮计分。T058 的严格拆篇规则、SC-001 既有公式保留。验收直接取 T075 三条**完整**彩排提示，另用回复无标题的写稿→省略式改稿→咨询夹具；运行时不读取用例及其标注。[三条彩排提示](../experiments/T075-article-training.md#限定-us2-的三条彩排提示词) · [当前编排](../../src/tu_assistant/chat/orchestrator.py) · [意图指标](../../src/tu_assistant/eval/metrics.py)

### 3. 稳定分配虚构代称

按初次出现的顺序分配类别内可区分、不带真实姓氏或角色前缀的代称，例如人名“甲某 / 乙某”、单位“甲单位 / 乙单位”。正文已有“职工”时形成“职工甲某”。首次分配或旧代称被后来明确披露的保护名占用时，才检查当前稿中已有称呼、全部已知候选和已分配代称，避开相同或会包含受保护全称的选择。短序列用尽后按类别加序号继续，直到无冲突。对已分配代称单查明确自报身份的语境，以覆盖其形式不在常规抽取范围内的情况；用户仅引用上一轮的虚构角色时继续复用。

后续稿同时出现“旧代称 + 原名”时继续复用旧代称。若后披露的身份确实占用旧代称，从当轮起重分配受影响的条目，并保护新披露的身份，既往已交付轮次保持当时结果。按长度优先处理重叠原名，一次扫描原有命中位置，避免替换产物被再次替换。断言同类多实体、同名跨轮、已有角色撞名、池耗尽、后披露冲突、顺序确定和再次处理的幂等性；普通虚构角色及职业称谓逐字保留。

### 4. 在出处校验生成文本时标出受保护的法条范围

`verify_output` 补缺失引文时插入的内容是换行、`> ` 和 KB 原文，末尾没有换行。原稿若在标记后同一行继续分析，最终 `>` 行便同时含原文和正文。P 的 005、008 初稿、010 初稿以及路线 A 三份选稿均可见这一现象。010 两次姓名泄露的位置均在案例段。需要用单独夹具复现“姓名出现在引文后粘连正文”这一风险。[出处校验及编辑代码](../../src/tu_assistant/citation/verify.py) · [T075 原稿与交付记录](../experiments/T075-article-training.md)

1. 在应用校验编辑时追踪最终交付文本中的半开区间 `[start, end)`，分别记录校正后的标记及 KB 确认原文的确切边界。覆盖原样命中、错版改写、错引替换、缺引文插入、不同长度及多处编辑的偏移；已核准的多行引文按实际匹配的原文字符定位。仅 `resolved_clause_id` 存在且 verdict 为 `ok` 或 `corrected` 的模型引用可标为核准。编排层拼接每份 KB 关联补条时按当次追加的标记、原文直接记位置。保留原有 `Citation.span/quote_span` 的原稿坐标供既有调用使用。
2. 按实际写入的片段传递位置。整行 `>`、对最终稿再拆 Markdown、对重复原文做全局查找都会误划正文。直接按区间检查：命中完全属于普通正文就替换，命中涉及核准标记或法条原文则整轮暂缓交稿。普通引用格式、裸引、未解析 / `incomplete` 的标记和引语不享有豁免，`not_found` 沿用删除占位。覆盖同一句 KB 原文在正文重现、多标记同一行，以及系统补条之前正文变长的夹具。
3. 冲突时用固定提示替换整轮，如“核准的条款出处或原文与本会话中需保护的称呼重合。为保留准确引文，本轮稿件暂缓交付。请用 /new 新建会话，以虚构称呼重新描述案情，或请项目方线下核对。”提示不复述原名、不含稿件、条款标记、引文或免责段；`citations=[]`、`question_count=0`。`extract_articles` 为零，`detect_refusal(...)["refused"]` 为假。不建议擅换法律依据，无需建立转交流程或落盘队列。
4. 测试至少断言两种结果：只有行末解释带保护名时，完整 KB 原文逐字保留、解释已替换且稿件照常交付；同一名称位于核准标记、核准原文或系统补条中时，返回固定提示。再测未核准引语命中可替换。整个实现无需改变模型提示词或顺带调整历史 Markdown 排版。

### 5. 交付、内部记录与评测数据

在助手轮加入 `Session.messages` 前完成处理，使 `Reply.content`、下一请求的助手历史与逐轮 `export_markdown` 同源。仅在 `Turn` 内存记录人名/单位替换次数和是否因引文冲突被拦截，会话保存候选与映射；`close`、CLI `/new` 后释放。用户原消息仍在当前本机会话中，线上日志不输出实体或对照表。

文章路径为 `Reply.citations` 构造安全交付值，四种 verdict 均检查所有可携带任意文本的字段，尤其 `raw`、`title`、`version_label`、`quoted_text`。已删除或已修正引文的原始元数据也须处理。保留可安全返回的判定、编号与 ID；因冲突暂缓交稿时返回空列表。普通模式 `raw_content` 为空，只有审定的合成评测可保留原稿。`run_eval` 本来即从 `final_raw` 调 `score_case_output` 重新校验条款，SC-011 继续从交付稿逐篇计数。[回复接口](../../src/tu_assistant/chat/assistant.py) · [评测运行器](../../src/tu_assistant/eval/runner.py)

仅在合成评测的 `_run_case` 中，于每次 `send` 后、`close` 前由 `TrainedAssistant` 内部读取本轮计数与拦截标志，单轮和脚本均记录。新 run 的报告按题号、轮次另列因引用冲突未交稿的轮数；零交稿不贡献 SC-011 分子或分母，该轮不被初筛为模型拒答。无需为 `Reply` 或公共 `Assistant` 协议增加审计字段。复审材料只列计数、分母和差异题号。
