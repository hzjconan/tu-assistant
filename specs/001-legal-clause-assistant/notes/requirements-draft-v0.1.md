## 1. 背景

需要构建一个面向法律类文档的智能助手。系统基于一批法律文档（公开数据），为用户提供两项核心能力：

1. **咨询**：回答用户关于某个问题所对应的法律条文；
2. **文档生成**：根据用户描述，识别相关法律条款，并生成违法场景的文字描述（例如"某人做了什么事、违反了哪些条款"）。

> 注：项目聚焦工会（trade union）领域的法律服务，目标用户为工会工作人员。正式需求以 `../spec.md` 为准，本文件仅作为 plan 阶段技术选型的素材。

项目方明确希望拥有**自有模型**（自己训练/微调的模型）。目前处于技术选型阶段，需要通过对比实验，确定"自训模型"、"RAG"或"二者结合"哪种方案更适合正式产品。

---

## 2. 目标

### 2.1 技术选型阶段目标
- G1：用对比实验确定正式阶段的技术方案，选型结论需有量化评测数据支撑。
- G2：保证选型实验的结论**可外推**到正式阶段的文档规模（约 1000 篇）。
- G3：沉淀可复用到正式阶段的资产：文档结构化数据、训练数据合成流程、评测集与评测流程。

### 2.2 正式阶段目标
- G4：基于约 1000 篇文档提供可上线的咨询与文档生成服务。
- G5：交付并部署项目方的自有模型。

### 2.3 非目标
- 本文档不涉及具体技术设计、代码结构与实现细节（见后续设计文档）。
- 不追求通用法律问答能力，仅覆盖项目文档范围内的内容。

## 3. 术语

| 术语 | 说明 |
|---|---|
| 条款 | 法律文档中的最小引用单元（条 / 款 / 项），具有唯一编号 |
| 行为规范条款 | 规定"应当 / 禁止"行为的条款，如"不得阻挠职工依法参加和组织工会" |
| 罚则条款 | 规定违反后果的条款（法律责任条款），如责令改正、恢复原工作、赔偿损失 |
| 关联条款 | 与某条款存在引用或适用关系的其他条款，典型如规范条款 ↔ 罚则条款 |
| 条款识别 | 根据用户的自然语言描述，找出对应的适用条款 |
| 构成要件 | 某行为被认定违反某条款所需满足的条件 |
| 自训模型 | 由项目方基于开源基座模型微调（LoRA / CPT / SFT 等）得到的模型 |
| RAG | 检索增强生成：先检索相关条款原文，再由模型基于原文作答 |

## 4. 用户与使用场景

### 4.1 用户
- 终端用户：通常**不能准确说出条款编号**，以口语化的语义描述或场景描述表达需求。

### 4.2 典型场景
- **S1 咨询**：用户描述一个问题或案情（如"公司未经工会同意把工会主席调到外地分公司，合法吗"），系统给出对应的法律条款及解释。
- **S2 文档生成**：用户以语义方式描述需求（如"生成几个用人单位阻挠职工组建工会的违法场景"），系统识别相关条款，生成场景描述：当事人做了什么、违反了哪些条款、应承担哪些法律责任。

## 5. 功能需求

### 5.1 核心流程

两个功能共享同一个核心环节：**条款识别**。

```
用户语义描述 / 场景描述
        ↓
   条款识别（共享核心）
        ↓
  ┌─────┴─────┐
 咨询回答    场景生成
```

### 5.2 需求列表

#### FR-1 文档入库与结构化
- FR-1.1 支持导入法律文档（格式待确认，见 §10）。
- FR-1.2 将文档按条 / 款 / 项切分为条款，每条记录至少包含：所属法规、条款编号、标题（如有）、原文。
- FR-1.3 支持维护条款之间的关联关系（至少包括规范条款 ↔ 罚则条款）。
- FR-1.4 支持文档的新增、修改、删除；正式阶段需支持增量更新。

#### FR-2 条款识别（共享核心）
- FR-2.1 输入为自然语言描述（口语化问题或场景），不要求用户提供条款编号。
- FR-2.2 输出适用条款列表，每条包含法规名称、条款编号、条款原文。
- FR-2.3 能将口语表达映射为法律概念（如"单位不让我们建工会" → 阻挠职工依法组织工会）。
- FR-2.4 能根据构成要件排除"看似相关但不适用"的条款，包括存在例外情形的情况。
- FR-2.5 能补全关联条款，至少包括相应的罚则条款。
- FR-2.6 一个描述可对应多个条款，系统需支持多条款输出。

#### FR-3 咨询
- FR-3.1 基于条款识别结果，回答用户问题并解释条款含义及适用方式。
- FR-3.2 回答中引用的条款编号与原文必须与入库原文一致。
- FR-3.3 回答需标明引用来源（法规名称 + 条款编号）。
- FR-3.4 对超出文档范围的问题，系统应明确告知"无法回答 / 不在知识范围内"，不得编造。

#### FR-4 文档生成（违法场景描述）
- FR-4.1 基于条款识别结果，生成违法场景的文字描述。
- FR-4.2 场景描述至少包含：事实经过（当事人做了什么）、违法行为认定、适用条款、处罚依据（罚则）。具体输出格式待确认（见 §10）。
- FR-4.3 场景中的行为必须满足所引条款的构成要件。
- FR-4.4 引用条款的编号与原文必须与入库原文一致。
- FR-4.5 对同一需求，支持生成多个在情境、情节轻重等方面有差异的场景。
- FR-4.6 是否支持"同时违反多个条款的综合场景"待确认（见 §10）。

## 6. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-1 | 准确性 | 条款编号与原文零差错；法律推理正确性为最高优先级 |
| NFR-2 | 可溯源 | 所有结论可追溯到具体条款原文 |
| NFR-3 | 抗幻觉 | 文档范围外的问题必须拒答；不得虚构条款 |
| NFR-4 | 自有模型 | 正式产品必须使用项目方自有（微调）模型，可私有化部署 |
| NFR-5 | 可更新 | 文档更新后，系统能在可接受周期内同步（周期待定） |
| NFR-6 | 规模 | 正式阶段支持约 1000 篇文档（预计数万条条款） |
| NFR-7 | 性能 | 响应时延、并发要求待定 |

## 7. 约束与假设

### 7.1 约束
- C1：文档为公开数据，无隐私限制，可使用外部大模型 API 进行数据合成与评测。
- C2：技术选型阶段在本机开发：Apple M1 Pro，32GB 统一内存，无 NVIDIA GPU。本机可进行 1.5B–7B 模型的 LoRA / QLoRA 实验（基于 MLX）。
- C3：正式阶段的训练在 GPU 环境中进行，不在本机。选型实验中的自训组允许短时租用云 GPU，以接近正式阶段的训练配置。
- C4：文档规模：选型阶段 30–50 篇；正式阶段约 1000 篇。

### 7.2 假设
- A1：可以收集到与项目文档同类型的公开法律文档（数百篇），用于规模扩展实验。
- A2：可以获取公开的真实案例（如行政处罚决定书、裁判文书），其中包含"事实描述 + 适用条款"，可用作训练数据和评测标准答案。
- A3：可以安排法律专业人员对评测结果进行抽检。

## 8. 技术选型要求

### 8.1 候选方案

| 编号 | 方案 | 说明 |
|---|---|---|
| A | 纯自训模型 | 知识通过训练（CPT + SFT）写入模型，推理时不检索 |
| B | 检索 + 通用模型 | 检索召回候选条款，由未微调的开源 / 商用模型判断与生成（基线） |
| C | 检索 + 自训模型 | 检索负责召回；自训模型负责语义理解、条款判断、关联补全及回答 / 生成 |

条款原文的展示统一以入库数据为准，不依赖模型记忆。方案 A 除外，因为 A 本身就是在验证"模型记忆"能否满足要求。

### 8.2 选型实验要求
- SR-1：三个方案使用**同一套评测集**和同一套评分标准。
- SR-2：**规模可外推**：核心评测题基于现有 30–50 篇文档；文档库逐步扩展（如 50 → 200 → 500 → 1000 篇，扩展部分使用同类公开文档），观察各方案指标随规模的变化。
- SR-3：自训组须采用与正式阶段一致或接近的模型规模与训练方式，不得仅以本机小模型结果代表自训方案。
- SR-4：检索组必须走真实的切分与检索流程，不得将全部文档直接放入上下文。
- SR-5：评测题的问法须与训练数据不同，避免测出来的是"背题"能力。
- SR-6：选型通过标准（阈值）在实验开始前确定（见 §9.3）。

### 8.3 选型阶段的预期产出
- 评测报告：各方案在各规模下的指标对比；
- 选型结论与建议；
- 可复用资产：条款结构化数据、关联关系表、训练数据合成流程、评测集与评测流程。

## 9. 评测与验收标准

### 9.1 评测集
- 规模：不少于 150–200 题，覆盖以下类别：
  - 条款识别（场景 / 问题 → 适用条款）
  - 多条款综合
  - 例外情形 / 边界情况（看似违法但实际不构成）
  - 文档范围外问题（应拒答）
  - 文档生成（违法场景描述）
- 来源：真实案例（优先）+ 人工编写 + 模型合成后人工校验。

### 9.2 指标

| 层级 | 指标 | 说明 |
|---|---|---|
| 主指标 | 条款识别召回率 | 标准答案中的条款被找到的比例 |
| 主指标 | 条款识别精确率 | 输出条款中正确条款的比例 |
| 主指标 | 关联条款完整率 | 罚则等关联条款被补全的比例 |
| 次指标 | 条款引用准确率 | 编号与原文是否与入库原文一致 |
| 次指标 | 拒答正确率 | 文档范围外问题被正确拒答的比例 |
| 次指标 | 咨询回答质量 | 解释是否正确、清晰（大模型评判 + 人工抽检） |
| 次指标 | 场景法律正确性 | 场景行为是否满足所引条款的构成要件 |
| 次指标 | 场景真实性与多样性 | 场景是否合理、多个场景之间是否有差异 |

### 9.3 选型通过标准
- 各指标的阈值待定（TBD），须在实验开始前确定。
- 原则：在主指标满足阈值的前提下，优先选择满足 NFR-4（自有模型）的方案。

## 11. 附：选型阶段的预判（仅供参考，以实验数据为准）

- 条款识别：方案 A（纯自训）在数万条条款规模下，预计在编号与原文准确性上明显落后于 B、C。
- 判断精度：方案 C 预计在构成要件判断、关联条款补全上优于 B。
- 文档生成：微调预计在格式统一、文风专业性上有明显优势。
